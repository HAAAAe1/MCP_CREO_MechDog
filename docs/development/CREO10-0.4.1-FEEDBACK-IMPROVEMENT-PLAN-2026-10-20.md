## 2. 本轮实现方案

**DEV-027：稳定构建指纹，兼容已有注册路径。**

- 保留 `json.hpp`：loader 和 payload 都实际使用它，删除依赖会造成错误复用旧 DLL。
- 在包内构建辅助模块统一处理仓库原生文本依赖：计算构建指纹前仅做 `CRLF→LF`；SDK、有效配置和现有构建判据继续参与计算。
- DLL、EXE、发布附件仍按原始字节计算完整性 SHA256；运行源码身份沿用现有规则。
- 区分“规范化构建指纹”和“物理世代目录键”。新缓存增加算法标识和 `generation_key`；现有 `setup.loader_fingerprint` 继续表示实际目录键，避免破坏使用方。
- 兼容旧缓存：读取四个依赖的一致快照，分别生成原始／LF／CRLF 形式，按原算法重算组合。只有旧指纹精确匹配、对应不可变 DLL 的 SHA256 正确，才复用原世代和注册路径。
- 无法证明等价时正常重建并说明原因；旧目录继续保留，被修改的不可变副本仍拒绝覆盖。worker 首次切换算法允许重编。
- 元数据逐文件原子发布，成功完成后才更新构建缓存标记；失败明确报错，下次持锁构建重新验证。不承诺多个元数据文件整体回滚。

**DEV-030：放宽显式编译环境输入。**

- Python 与 PowerShell 统一为：必须包含大写 `INCLUDE`、`LIB`、`PATH`，其余键接受并忽略。
- 仅三项必需值进入构建脚本和有效配置；额外值不执行、不透传、不影响构建指纹。
- 缺键错误列出缺失项和最小配置示例；忽略提示仅列键名，不回显值。Python 日志写 stderr，保留 MCP stdout。
- 安装回写规范化后的三键，同时保留配置文件其他属性；缺省／null 及显式 vcvars 路径的既有优先级保持。
- 不新增 MCP 工具，不修改原生回调 ABI 或协议。

## 4. 测试与验收标准

| 层次 | 必须覆盖的结果 |
|---|---|
| 指纹回归 | LF／CRLF 等价；JSON 实际内容变化使相关产物失效；worker 专用改动不重编两个 DLL |
| 旧缓存迁移 | 首次及第二次构建均复用旧世代；注册内容、DLL SHA、目录数量保持；损坏或无法证明等价时不误用缓存 |
| 失败路径 | 元数据发布中断后不误报成功，不覆盖旧不可变副本；重新进入能够验证并收尾 |
| 环境兼容 | 三键、额外键、缺键、大小写及非法值；确认忽略项未进入脚本，Python／PowerShell 行为一致 |
| SDK／安装 | 本机匹配 SDK 编译、解压安装和连续构建；记录编译决策、指纹、注册文件 SHA 与目录变化 |
| 统一检查 | 针对性回归及 `tools/dev_check.py` 通过，无新增诊断或基线豁免 |

实机前重新确认会话可操作，只使用 E 盘 `MCP_CREO_MechDog_dev`。WorkBuddy 仅做公开 MCP 黑盒验收；文件层构建检查与实际回调启动分别记录。已有 16/16 黑盒结论保留其具体范围，不扩写为所有分支通过。
