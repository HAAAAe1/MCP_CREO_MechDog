## 使用规则

- 固定 ID 不复用：BUG 为缺陷，FEAT 为能力，DEV 为工程与验证。新增工作先登记目标、范围、验收与环境；复杂条目使用[模板](templates/WORK_ITEM.md)。
- 状态：待规划、待核实、待开发、开发中、验收中、已完成、阻塞、取消。待规划/待核实须补齐范围、复现与可判断的验收，才能进入待开发；阻塞注明依赖，取消保留原因。完成后将条目及证据链接移入归档。
- P0 指长时间通道封锁、会话损坏或恢复不可用的紧急稳定性问题。报告编号仅用于溯源，不能代替固定 ID；优先级、实现、测试执行结束和验收通过分别判断。
- 当前开发与发布按本机 Windows x64 / Creo 12.4.0.0 / 匹配 SDK 的实际改动范围验收；不要求 Creo 10 独立复测或双版本验收，不因缺少 Creo 10 结果阻塞完成、合入或发布。朋友反馈具体问题后再登记或沿用 ID 跟进；历史环境与未测事实保留，不跨环境外推。WorkBuddy 只通过 MCP 做黑盒验收，开发者测试另记；具体要求见[开发入口](DEVELOPMENT.md#workbuddy-测试约定)。版本号、历史成功或文档登记均不能代替本次验证。
- 每个 ID 仅保留一条当前记录，部分范围通过仍须注明未完成边界；工作卡、版本记录和历史报告补充本表，不另排平行计划。
