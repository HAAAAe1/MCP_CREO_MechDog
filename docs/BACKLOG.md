## 使用规则

ID 一经分配不复用：`BUG` 为缺陷，`FEAT` 为能力，`DEV` 为工程与验证。目标版本未确定时写“未排期”。状态为待规划、待核实、待开发、开发中、验收中、已完成、阻塞或取消；待规划/待核实条目须补齐范围、复现和可判断的验收才能进入待开发。阻塞写明依赖，取消保留原因，已完成链接本次证据。

P1 稳定性优先。建议执行顺序为 BUG-002 → BUG-001 → FEAT-001 → BUG-003；BUG-004 在实验兼容环境核实。功能拓展先建立独立验收范围，再排期。下表验收摘要不是已经通过的结论；详细来源保留在 [原问题快照](待完善功能清单.md)，复杂工作使用 [模板](templates/WORK_ITEM.md)。
