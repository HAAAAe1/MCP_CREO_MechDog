## 三、核心问题详述

### P0-1 `creo_new_airfoil_blade` 完全不可用：打包种子库无法被本机 Creo 加载

**严重程度**：P0（功能完全不可用）

**复现步骤**：
1. `creo_new_airfoil_blade(stations=[{chord:100, offset:0, ...}, {chord:80, offset:150, twist_deg:20, ...}], interpolation="smooth")` → 失败
2. 换 `interpolation="straight"`（选 two_straight 种子）→ 同样失败
3. 两个不同种子均失败，错误一致：`toolkit_code=-16`，`ProMdlFiletypeLoad(file,PRO_MDLFILE_UNUSED,PRO_B_FALSE,&loaded)=-16`，`BUILD_FAILED=-16`

**证据链**：
- 种子文件存在且字节完整：`seed_library/seeds/two_smooth/mechdog_smooth_reference.prt.4`（116,535 字节），`creo_list_seeds` / `creo_validate_seed` 均报告 `available: true`、SHA256 与清单一致。
- Python 编排层正常：种子快照已复制到 job 输入目录，native 层的隔离复制也成功（`ls_<jobid>.prt.1` 生成且大小一致），工作目录切换成功。
- 仅 `ProMdlFiletypeLoad` 一步返回 -16。

**根因分析（文件头版本不兼容）**：对比 Creo 文件头（UGC）：

| 文件来源 | 头部标识 |
|---|---|
| 全部 9 个打包种子 | `PART 2128 1860 810 1 1 15 4100 2023073` |
| 本机 Creo 9.0.0.0 自带模板 | `PART 1934 1460 800 1 1 15 3700 2019344` |
| 本会话 Creo 生成的模型 | `PART 2023 1760 810 1 1 15 4000 2022073` |

种子文件是由**比本机 Creo 9.0.0.0 更新的构建**（头部 2128/2023 年构建）保存的，旧版 Creo 拒绝加载新版文件 → -16。本机唯一安装即为 9.0.0.0（进程路径已验证），无其他版本可回退。

**次生问题（检测盲区）**：`creo_validate_seed` / `creo_list_seeds` / `creo_install_seed_library` 都只校验**文件哈希与清单元数据**（"native_validation: Performed ... when creo_new_loft_part creates the model"），无法提前发现原生加载不兼容。用户看到的全是"available: true"，直到调用 blade 工具才失败，且失败信息是笼统的 "Toolkit operation failed; inspect native.log"，需要翻原生日志才能定位。

**建议**：
1. 用与目标 Creo 版本兼容的构建**重新生成种子库**并随版本分发（或在文档中明确种子库所需的最低 Creo 版本）。
2. `validate_seed`/`list_seeds` 增加**原生加载探针**（在隔离副本上试加载），把版本不兼容提升为显式错误。
3. 种子加载失败时给出明确错误信息，例如："种子文件由更新版本的 Creo 保存（UGC 2128），当前 Creo 9.0.0.0 无法加载"。

### P0-2 `creo_rib` 在所有测试中均失败（特征再生失败）

**严重程度**：P0（功能完全不可用）

**复现步骤**（4 次尝试，全部失败）：
1. 筋线 (15,40)→(30,55)（起点在实体表面）+ `thickness=3, side=symmetric, flip=false` → 失败
2. 同轮廓 + `flip=true` → 失败
3. 筋线 (5,40)→(25,60)（起点在实体表面，上方悬空区域减少）→ 失败
4. 筋线 (5,30)→(25,60)（**起点在实体内部，明显穿过实体**）→ 失败

**失败模式一致**：`toolkit_code=-1`，"Regeneration produced a failed, suppressed or incomplete feature"；native.log 显示 `ProFeatureWithoptionsCreate=0`（**特征创建 API 本身成功**，created_feature_id 正常分配），但 `ProSolidRegenerate=0` 后特征状态为 **6（failed）且 geometry_items 为空**。每次失败均正确回滚到存档点（rollback_succeeded=true），未损坏模型。

**实现线索**（来自 `native/surfaces.cpp` 的 `generic_rib`）：采用两阶段创建——先以 `PRO_FEAT_CR_INCOMPLETE_FEATURE` 创建，再 `ProFeatureElemtreeExtract` → 重设 `PRO_E_RIB_SECTION_COMP/PRO_E_STD_MATRLSIDE` → `redefine`。`PRO_E_FEATURE_FORM=PRO_EXTRUDE`。

**分析**：4 种合理轮廓（含教科书式"从实体内部穿出到自由空间"的轮廓）× 2 种材料侧设置全部失败，且失败发生在再生阶段而非参数校验阶段，怀疑两阶段 create+redefine 流程在该 Creo 版本上留下了不完整的元素树（例如 MATRLSIDE 重定义未生效或 section 引用丢失）。也可能是轮廓/草图平面要求与实现假设不符（我的草图位于实体表面平面 y=0 上）。

**建议**：
1. 请作者在交互式 Creo 中用**同一条轮廓**手动创建筋特征对比，确认轮廓本身满足要求后，再排查两阶段 create+redefine 流程。
2. 在 MCP 层对筋特征做创建后自检（特征 status/geometry_items 检查已有，但请把原生失败原因——如"截面未与实体相交"——提取到错误信息中），避免只能看到笼统的 "Regeneration produced a failed..."。
3. 若确认是实现缺陷，建议改为单阶段完整元素树创建（参考 `generic_hole`/`generic_round` 的单次 create 流程）。

### P1-1 `dimension_pattern` 在已抽壳零件上产生异常几何：体积不降反升

**严重程度**：P1（结果错误且难以察觉）

**复现步骤**（在已 `shell(2mm)` 的零件上）：
1. 零件：80×50×20 块体 + 旋转体 + 抽壳(2mm) + Ø10×10 盲孔 ×3（一个原始 + 两个已有阵列成员）。
2. `creo_dimension_pattern(feature="hole1", dimension_id=80, count=3, increment=-15)` → **成功**，两个新孔位置正确（(45,35)、(30,35)，孔径/深度均正确）。
3. **但体积从 41820.01 mm³ 增加到 43327.97 mm³（+1507.96）**，而正确行为应为**减少**约 314 mm³（每个新孔只切穿 2mm 顶壁：π×5²×2×2 ≈ 314）。

**证据**：模型检查显示两个新孔周围出现了 **r=7（孔径+壳厚）的圆柱面**（z 8..18），即孔周围裹了一圈 2mm 厚的材料"环箍"——这正是抽壳的 2mm 偏移量。这说明**抽壳特征被异常地围绕新阵列孔重新求值/偏移**。在交互式 Creo 中，阵列成员创建于抽壳之后，只会切穿顶壁，不会形成环箍。

**对照**：同模型上的 `axis_pattern` 无此问题——体积减少量 106.03 与解析值（2 个整孔 42.41 + 1 个半孔 21.2）**精确一致**。

**分析**：疑似 `dimension_pattern` 的实现通过临时修改 leader 尺寸并复制特征，过程中触发了全树再生（含 shell），导致壳壁在新孔位置重新偏移；而 `axis_pattern` 走的是原生 ProPattern 路径，无此问题。

**建议**：检查 `dimension_pattern` 的实现路径，避免中间态触发依赖特征（shell）的重新偏移；或改用原生 dimension pattern API。建议增加"阵列后体积方向"的回归测试（孔阵列必须使体积减少）。

### P1-2 `component_constraints` 应用约束后元件位置不重新求解

**严重程度**：P1（约束与几何状态不一致）

### P1-3 部分显式草图尺寸类型在原生层失败（`ProSecdimCreate = -2`）

**严重程度**：P1（文档未声明的限制，且失败即整体回滚）

对 11 种草图尺寸类型逐一实测，得到如下可用性矩阵：

| 尺寸类型 | 引用形式 | 结果 |
|---|---|---|
| length | 1 个 whole 实体 | ✅ |
| radius / diameter | 1 个 whole 实体 | ✅ |
| arc_angle | 1 个 whole 实体 | ✅ |
| ellipse_x_radius / ellipse_y_radius | 1 个 whole 实体 | ✅ |
| angle | 2 个 whole 实体 | ✅ |
| line_distance | 2 个 whole 实体 | ✅ |
| horizontal / vertical | 2 个**点**引用（start/end） | ✅（值正确：100/60） |
| **horizontal** | **1 个 whole 实体** | ❌ ProSecdimCreate=-2 |
| **vertical** | **1 个 whole 实体** | ❌ ProSecdimCreate=-2 |
| **distance** | **2 个 whole 实体** | ❌ ProSecdimCreate=-2 |

**附带发现**：horizontal/vertical 用点引用标注**两条相邻边**时，尺寸会吸附到两边的共享顶点，测得 0（如 rect1_0.start 与 rect1_1.start 标注 horizontal 得 0.0 而非 100）。点引用对非相邻实体则完全正确。

**影响**：上述三种"失败组合"会使整个草图作业失败并回滚（错误仅体现在 native.log 的 `ProSecdimCreate=-2`，MCP 层无任何提示）。

**建议**：
1. 在工具文档中明确列出受支持的尺寸类型 × 引用形式组合。
2. 在 Python 校验层直接拒绝已知失败组合，给出可读错误（如 "vertical 单实体引用不受支持，请使用两个点引用"）。
3. 评估是否可以在原生层修复（例如单实体 horizontal/vertical 自动转换为该线两端的点引用）。

## 四、一般问题与改进建议（P2）

1. **引用格式错误的报错延迟且晦涩**。`creo_hole` 的 `reference1/2` 传 `{"kind":"datum_plane","id":2}`（id 形式）时，直到 Creo 再生才失败（特征 status 6、无几何体）；传 `{"kind":"datum_plane","axis":"x","offset":60}` 时报 "Plane reference must identify exactly one surface"——因为 datum_plane 引用里的 `offset` 是用于**匹配模型中已存在的平面位置**，不是孔到基准面的尺寸偏移（后者应走 `offset1/offset2` 参数）。建议：对 datum_plane 引用中 id 与 axis 混用、hole reference 携带 offset 等情况给出明确的参数校验错误。
2. **草图实体引用错误的报错暴露内部实现**。传不存在的实体名时，pydantic 错误信息包含 60+ 个内部 op 类型名的完整 union dump（约 96KB），真正的错误（"Unknown sketch entity reference: rect1"）被淹没。建议精简为单行可读错误。
3. **`creo_transform_geometry` 不支持坐标系引用**。`{"kind":"datum_feature","label":"csys1"}` 失败于 `ProFeatureGeomitemVisit(PRO_SURFACE)=-4`（坐标系特征没有曲面几何）；基准面可正常变换。工具描述称支持 "datums"，建议明确支持范围或兼容 csys。
4. **`creo_set_parameters` 的布尔值被存为实数**。`{"WB_OK": true}` 被存为 type 52（REAL）值 1，而非布尔类型；文档声称支持 booleans。
5. **`creo_thicken(new_body=true)` 未产生独立实体**。同参数据下 `creo_extrude(new_body=true)` 能正确产生第二个 body（bodies: 1→2），而 thicken 只是把不相交团块并入同一 body（bodies 仍为 1）。两者行为不一致。
6. **钣金模型的 body 列表含"幽灵 body"**。第一壁转换后 inspection 报告 2 个 body：一个正常（bbox 完整），另一个 `id=-5778`、无 bbox。可能影响按 body ID 引用的工具（如 `boolean_bodies`）。
7. **装配约束的 offset 对非 _OFF 类型被静默忽略**。`mate`/`align` 携带 offset 时存储为 0（需用 `mate_offset`/`align_offset`）。建议校验时报错或警告。
8. **`creo_list_models` 返回体量过大**。单次响应 781KB（含全部模型完整快照），超出工具返回上限被写盘。建议提供精简模式（仅名称/类型/revision/状态）。
9. **失败模型无恢复/清理路径说明**。两个失败的 blade 模型在 `list_models` 中显示 `status=failed, revision=0`，文档未说明如何恢复或清理。
10. **`creo_new_airfoil_blade` 与 `creo_loft` 的关系建议明确**：blade 工具依赖种子库（当前不可用），而 `creo_loft` 直接用草图截面可用且正确——可在 blade 失败时提示用户改用 `creo_loft` 手动搭建多截面混合。
