# MCP_CREO_MechDog 问题反馈报告

- **日期**：2026-10-16
- **MCP 名称**：MCP_CREO_MechDog
- **MCP 版本**：0.3.1（`creo_capabilities` 返回 `version: 0.3.1`，`tool_count: 82`）
- **Creo 环境**：Creo Parametric（xtop.exe）本机自动启动，`units: mm`
- **复现任务**：《配电箱_跨软件自然语言建模说明.txt》——由文字描述从零建立薄壁配电箱（箱体 + 门板 + 打开姿态装配），全程只调用 MCP_CREO_MechDog，几何 100% 来自该 TXT，未导入任何外部实体
- **结果概览**：箱体（210 特征 / 1 实体 / 体积 126 264.45 mm³）与门板（38 特征 / 1 实体 / 体积 35 848.59 mm³）均建成并单实体化，装配 2 组件、变换与 TXT 轴映射完全一致；但过程中遇到 10 项可用性/功能缺陷，其中 2 项为**阻塞级**

## 一、阻塞级问题（导致特征无法按语义建立）

### P1. 多区域（互不相邻多环）截面做**拉伸增料**必然失败，而同样多环做**切除**正常

- **现象**：一个草图内含 2~6 个**互不相邻**的闭合环，做 `extrude(mode="add")` 时统一报
  `Toolkit call ProFeatureWithoptionsCreate failed with code -1 during execute_extrude`（`toolkit_code: -1`）。
  同一批几何，若把每个环拆成独立草图 + 独立拉伸，则**逐个成功**。
- **关键对照实验**（同一模型 `fb8c5b7fc3604dd1a3756071678c9397` / `3eca200ecc254cd3a0062b921dd4379d`）：
  | 场景 | 环数 | 结果 |
  |---|---|---|
  | 百叶罩截面拉伸（1 环） | 1 | ✅ 成功 |
  | 百叶罩截面拉伸（2 环，不相邻） | 2 | ❌ 失败 |
  | 百叶罩截面拉伸（6 环，不相邻） | 6 | ❌ 失败 |
  | 壁面 D 形通风切口切除（6 环，不相邻） | 6 | ✅ 成功 |
  | 箱体水平框边（外框+内框，2 环**嵌套**） | 2 | ✅ 成功 |
  | 门板四边折边（外框+内框**嵌套**） | 2 | ✅ 成功 |
- **结论**：`extrude` 的增料路径只接受「**单个区域（可含内孔）**」；一旦截面含多个互不相邻区域即失败。而 Creo 本身完全支持多区域拉伸截面。**这直接迫使建模人把 12 个百叶罩从 2 次调用膨胀为 12 次调用，并放弃「6 槽一刀切」以外的批量写站。**
- **违反能力声明**：`creo_capabilities` 未对 `creo_extrude` 声明该限制（`creo_loft` 反而明确写了 "default-body add only ... rejected"），文档与实现不一致。
- **建议**：参考 `creo_loft` 的写法，在 `creo_extrude`/`creo_revolve` 的能力与描述中显式声明「add 模式仅支持单区域截面」；或修复为多区域。若短期无法修复，至少应返回**可识别的业务错误码/消息**（如 `MULTI_REGION_PROTRUSION_UNSUPPORTED`），而不是裸的 `code -1`。
- **复现 job**：`6c7506ce1ff64c10ad089390f955e19e`（2 环失败）、`41392120ece64a5e9bec671bae1ac9ad`（6 环失败）、`8c5fe7850ad54a8b86bfc66c364905d6`（6 环切除成功）

### P2. 增料特征与既有实体**仅共面接触**时无法合并；必须存在体积重叠

- **现象**：百叶罩的根部按 TXT 语义应"回到侧壁内表面"，即与壁面**面贴合**（法向共面）。此时
  - `extrude(mode="add", new_body=False)` → `ProFeatureWithoptionsCreate failed with code -1`
  - 同样几何 `new_body=True` → ✅ 成功，但生成**第二个 body**（`bodies: 2`）
  - 失败原因不是几何非法（`new_body=True` 可证），而是**共面接触不被当作可合并**。
- **影响**：所有"贴合装配式"特征（百叶罩根部、门板铰链耳与折边、底板凸台根部、铰链销与座）都需人为制造"暗藏咬合"。本次被迫把百叶罩根部改成
  `C(91.5,Y1) → (92.0,Y1+0.5) → (93.0,Y1+0.5) → (92.5,Y1)` 的**斜置四边形咬合舌**（1 mm 咬入侧壁内部），才使 `add` 成功并保持单实体。
- **附带发现的坑（同类）**：为制造咬合而加"竖直直角舌"会产生**尖点（cusp）**截面——
  根弧在 180° 处切线为竖直，竖直舌边与之**反向共线**，截面被拒，同样只报 `code -1`；把舌边改为**斜边（与圆弧切线成 45°/135°）**才通过。
- **建议**：
  1. `add` 的合并判定应容忍共面接触（Creo 原生 protrusion 即可 union 共面实体）；
  2. 不能容忍时，请返回明确错误，并在文档中给出"需要体积重叠"的建模指引；
  3. 增加**截面合法性预检**（自交/尖点/退化）并返回可读原因。
- **复现 job**：`821e2459c33943d99da2f81876037732`（共面 add 失败）、`be5b4b1caf9044b992951d847e457a06`（同几何 new_body=True 成功、bodies=2）、`8f3d466d6d9547caaef7b8b5d21ecc56`（竖直舌尖点失败）

## 二、接口与文档一致性问题

### P3. `plane` 字典形式的 `{kind:'datum_plane', axis:'x', offset:91.5}` 不被接受

- **现象**：`creo_create_sketch`/计划里的 `sketch.plane` 使用 `creo_capabilities → references` 中给出的写法
  `{"kind":"datum_plane","axis":"x","offset":91.5}`，报
  `Plane reference must identify exactly one surface; inspect the model and use a surface ID`。
  而 `creo_capabilities` 明确把该写法列为 datum_plane 的规范示例。
- **实际可用路径**：必须先 `creo_datum_plane(label, reference={kind:'datum_plane',axis:'x',offset:0}, offset=91.5)` 显式建面，再用 `{"reference":{"kind":"datum_feature","label":"<label>"}}` 引用。
- **建议**：要么让 `offset` 在字典形式下生效（自动建面），要么修正能力文档，并在报错信息里直接提示"请先创建 datum_plane 并按 label 引用"。

### P4. `polyline` 实体在拉伸阶段静默失效

- **现象**：把闭合环中的一段直线写成 `{"type":"polyline","points":[...],"closed":false}` 时，草图创建成功，但后续 `extrude` 报 `code -1`；改写成等价的 2~3 条 `line` 后通过。
- **注意**：该现象与 P2 的"尖点"叠加时不易区分——建议对 polyline 做与 line 一致的连接性/相切性校验并给出差异提示。

### P5. `creo_assemble_component` 的旋转欧拉角方向与直觉相反，且无验证提示

- **现象**：按 TXT 要求门板需 `local +X → global −Z、+Y→+Y、+Z→+X`（等价 **+90° 绕 Y**）。传入 `rotation:[0,90,0]` 得到的实际矩阵是
  ```
  [[0,0,-1],[0,1,0],[1,0,0]] → 即 Ry(−90°)
  ```
  即局部 +Z 映射到 global −X（与要求相反）。改为 `rotation:[0,-90,0]` 后得到
  ```
  [[0,0,1],[0,1,0],[-1,0,0]] → Ry(+90°) ✅
  ```
- **验证方式（建议内建）**：装配后可用 `creo_list_components` 读 transform 复核。本次复核结果：
  门板孔起点 (82.5, 65, 6) → 全局 (−82.5, 61, 85)，与箱体销起点 (−82.5, 61, 85) **完全一致**；第二孔 (82.5, −70, 6) → (−82.5, −74, 85) 同样一致。
- **建议**：在 `creo_assemble_component` 文档中写明欧拉角**施加顺序与手性**（当前描述 "applied X then Y then Z" 不足以定位手性），或在返回中直接回显 4×4 变换矩阵，便于建模方自查。

### P6. `creo_list_components` 输出过大且无 `detail` 参数

- **现象**：2 个组件的装配，返回 **170 512 字符**，超过工具返回上限，被强制落盘为文件。而同族的 `creo_get_job`/`creo_inspect_model`/`creo_list_models` 都有 `detail: compact|full`。
- **影响**：想读"组件名 + 变换矩阵"这一小段信息，必须读取 170 KB。
- **建议**：为 `creo_list_components` 增加 `detail=compact`，只回 feature_id / model_name / transform / placement / underconstrained。

### P7. `creo_capabilities` 输出 **98 293 字符**，超出单次返回上限

- **影响**：能力说明是接入方唯一的权威文档来源，却无法在一次调用中读完（必须依赖落盘文件 + 分段读取）。
- **建议**：按 `section` 参数切分（如 `frames` / `references` / `tools` / `limits` / `tests`），默认只回摘要。

## 三、可观测性与诊断问题

### P8. 失败诊断信息不足以定位

- **现象**：失败时 `creo_get_job` 只给出 `failed_stage: execute_extrude` + `failed_toolkit_call: ProFeatureWithoptionsCreate` + `code -1`；`native_log_tail` 里**全是成功返回的 inspection 日志**（`ProSurfaceIdGet(...)=0` 等），并不包含失败调用的上下文（哪个草图的哪条环、截面拓扑、报错面）。
- **影响**：建模方无法区分"截面非法"与"合并失败"（P1/P2/P4 三种原因报同一句话），只能用二分法试错，本次为此多消耗了 6 次全量重建（每次 2~4 分钟）。
- **建议**：
  1. `failed_operation_index` 已经很好，请再补 `failed_operation_label` 与 `failed_sketch_entities`；
  2. 把 native log 切成"失败调用前后各 N 行"而非尾部摘要；
  3. 对 `code -1` 做二级归因（截面非法 / 无法合并 / 特征超出父特征范围 …）。

### P9. 长任务无进度反馈

- **现象**：20 个操作的计划（`8c5fe785...`）耗时 2 min 20 s，16 个操作的格栅计划（`a6c8e966...`）耗时 5 min 02 s，`creo_get_job` 全程只有 `status: running, stage: connect/executing_feature_plan`，**无 `completed_operations/total`**，只能盲等轮询。
- **建议**：在 compact 详情里返回 `completed_operations` / `current_operation_label`。

### P10. 失败即整批回滚，但回滚信息不够显式

- **现象**：多操作计划首错即停并回滚（`rollback_succeeded: true`），这是好设计；但 `result.operations` 返回空数组，调用方无法知道**哪些操作已经成功执行过**（也就无法只重跑后半段）。本次遇到"18 个操作成功、第 19 个失败"时必须整批重发。
- **建议**：回滚时返回 `operation_outcomes: [{index, label, succeeded}]`，并在文档中建议"把大计划切小批"。

## 四、正面反馈（值得保留的设计）

1. `creo_startup_status` + 后台自动启动 xtop，`units: mm` 全程一致。
2. `creo_execute_plan` 的"**失败即整体回滚 + 落盘快照 + reload 校验**"很可靠：本次 10 余次失败均未污染模型。
3. `creo_inspect_model` / `creo_get_job(detail=compact)` 的 `volume_mm3 + counts(bodies/features)` 让每一步都有客观验收值（本次每批次都用体积增量核对了特征是否真正生效）。
4. 原始特征均为**原生可编辑特征**（草图/拉伸/旋转/平面），可在 Creo 特征树中回改尺寸，符合"从零建模"要求。
5. `creo_datum_plane` + `{kind:'datum_feature',label:...}` 的引用链路稳定，是绕开 P3 的可靠写法。

## 六、本次建模采用的替代做法（因上述缺陷而偏离 TXT 直译）

1. **百叶罩根部**：由"面贴合"改为"**1 mm 斜置咬合舌**"（咬入侧壁内部，最终几何在实体内部被吸收，外观不变）。
2. **百叶罩两端圆滑端部**：省略（TXT 5.3 的 ±10 处 90° 旋端），仅保留 20 mm 直段等厚薄壳。
3. **百叶罩批量**：由 2 次调用（每侧 1 次）拆为 **12 次单环拉伸**。
4. **格栅**：由"保留三圈环筋 + 四直径条带的并集后切除"改为「切入 45 圆 + 4 条直径条带 + 3 组环筋分别增料」，每侧 8 次调用。
5. **底板凸台根部**：加"**0.5 mm 三角咬合**"以确保旋转壳与底板合并。
6. **铰链座/销、门板耳**：向父特征内部各**多伸 1 mm**（隐藏重叠），保证合并为单实体。
7. **边角折弯释放/圆角**：未做（TXT 允许近似）。

> 以上均为**已披露的近似**，不构成对原模型的严格几何复现。
