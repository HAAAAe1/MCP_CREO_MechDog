## BUG-070 取证与根因

- 复现：本机 status 探针恒返回同形态乱码（`▩STB_3395F2E70001`、`▩FEAT042_SEED_PART0001`、用户环境 `▩0010001`）。
- 取证：`subprocess` 携 `bridge.native_environment()` 直跑 `creo_worker.exe status 5`，stdout 原始字节 `… 22 3a 22 e2 96 a9 53 54 42 …`——U+25A9（UTF-8 e2 96 a9）在 JSON 序列化前、native 层即存在，排除编码转换/序列化/客户端显示层。
- 根因：worker.cpp status 探针使用 deprecated（since Creo 3，ProMdl.h:595 SUCCESSORS: ProMdlMdlnameGet）的 `ProMdlNameGet`；`ProName value` 未初始化且未检查返回值，API 失败时 connect 阶段 Toolkit 内部栈残留（0x25A9+名+0001 结构）暴露为模型名。
- 修复：`ProMdlName value = {}` + `ProMdlMdlnameGet` + 返回值检查（失败置空名）+ `name_read_code` 诊断字段；未在 Python/客户端层清洗字符。

## BUG-069 方案与实现

用户 2026-10-18 确认"放宽+小写规范化"：`MODEL_NAME` 正则 `[a-z][a-z0-9_]{0,30}` → `[a-z0-9][a-z0-9_]{0,30}`；新增 `bridge.normalize_model_name`（lower + fullmatch，错误信息含完整规则与大写规范化说明）；plate / generic submit / adoption apply 三个校验点统一；工具描述同步（new_part docstring、adopt 工具 model_name 描述）。
