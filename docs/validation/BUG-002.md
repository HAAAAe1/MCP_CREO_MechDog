## 根因与修复

当前分支隔离复现：串行双文件各 100 次均成功；3 个读线程、400 次写入、5 轮，分别测试 job.json 和 model.json，共 4,000 次写入中 3,978 次失败（全部 WinError 5），读取错误 79 次。固定普通读句柄稳定触发，释放后恢复；清理前共留下 3,982 个临时文件，统计保存后关闭线程/句柄并删除夹具。

普通 CRT 读取没有共享删除访问；进一步验证发现，本机 NTFS 上 MoveFileEx（Python os.replace）即使面对共享删除句柄仍会拒绝替换。修复使用共享读/写/删除的 CreateFileW 读取句柄，以及 SetFileInformationByHandle 的 FileRenameInfoEx、REPLACE_IF_EXISTS | POSIX_SEMANTICS 单步替换。旧句柄继续读取完整旧版本，新打开的句柄读取新版本，不先删除目标。依据：[CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)、[FILE_RENAME_INFORMATION](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information)。

仅明确不支持扩展重命名的错误 1/50/87 回退原子 os.replace。没有选用 ReplaceFileW，因为该接口的部分失败状态会移除原目标，见 [官方失败语义](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)。替换阶段仅 Windows 错误 5/32/33 重试：1 秒总预算，5 ms 起指数退避、最多 50 ms，最多 25 次尝试。只读目标立即失败；错误 5 可能是 ACL 拒绝，无法单凭错误码判为可恢复竞争，持续拒绝仍有界报错。

保持 UTF-8/BOM 和 JSON 读取异常、revision 防护、原生成功/失败/未知结果判定。临时文件独占创建，写完关闭后替换；序列化、创建、写入异常不重试。失败只清理本次已创建的临时文件，清理失败附加诊断并保留主异常。

## 边界与另一台机器复测

- 本次是 Windows 11 / NTFS / Creo 12.4 的当前源码证据。Creo 10、其他 Windows/文件系统、网络共享及外部安全软件组合没有实机验收；扩展接口回退只做确定性单元验证。
- 并发实机脚本运行真实提交、runner、worker，隔离路径通过进程内覆盖 jobs/models 实现，只抑制 detached 启动。detached MCP 链路由 general/guards 单独验证，未同时叠加并发实机脚本。
- 模型和任务终态分属两个文件，没有跨文件事务。持续终态写失败会保留 native_result.json、保存模型及最后有效登记，异常/重试上下文可在 runner.log 的 traceback 中追踪；不会自动重复原生操作或伪造几何失败。可能保留 pending_job 或出现模型已完成而任务仍 running 的状态，受控恢复仍归 BUG-001。
- 服务版本仍为 0.2.5；DEV-001 分支尚未并入远端 main。本分支依赖该规范提交，BUG 修复 PR 应先以 `codex/development-standards` 为比较基线，规范合并后再核对 main。
