## 三、核心问题

### P0-1（未修复）`creo_new_airfoil_blade`：打包种子仍无法被 Creo 9 加载

**复现**：`stations=[{chord:100,offset:0},{chord:80,offset:150,twist_deg:20}]`，`interpolation="smooth"` 与 `"straight"` 各试一次，均失败。

**现象**：`toolkit_code=-16`，`ProMdlFiletypeLoad(file, PRO_MDLFILE_UNUSED, PRO_B_FALSE, &loaded)=-16`，失败阶段 `connect`。

**证据**：
- 种子库与 0.3.0 完全相同（文件时间戳 Oct 14 18:54，UGC 头 `PART 2128 1860 810 ... 2023073`）；RELEASE_NOTES_0.3.2 也明确"九个种子 PRT 的 SHA256 保持不变"。
- 本机 Creo 9.0.0.0 自建文件头为 `PART 2023 1760 ...`，安装自带模板为 `PART 1934 1460 ...`——种子由更新的构建保存，旧版拒绝加载。
- `creo_list_seeds`/`creo_validate_seed` 仍只校验哈希，全部显示 `available: true`，检测盲区未变。

**改进确认**：0.3.2 的错误信息已明显改善（明确指出失败的 API 调用与阶段 `connect`），👍。

**建议**：
1. 在 `creo_validate_seed`/`creo_install_seed_library` 中增加**原生加载探针**（隔离副本试加载），把版本不兼容在建模前暴露为显式错误。
2. 发布物按 Creo 大版本提供配套种子库（至少给出"种子库最低 Creo 版本"的元数据并在安装/校验时核对）。
3. 文档中明确 `creo_new_airfoil_blade` 的环境要求；在 Creo 9 等旧版环境下引导用户改用 `creo_loft`（本环境已验证可用且几何正确）。

### P0-2（Creo 9 未修复）`creo_rib`：筋特征在 Creo 9.0.0.0 上仍然失败

**复现**（本环境 4 次尝试）：
1. execute_plan 中 底座 100×80×15 + XZ 平面竖线 (0,15)→(0,45)（起点在底座顶面）+ `rib(thickness=3, side=symmetric, flip=false)` → 失败："Rib regeneration failed on the requested material side..."
2. 同轮廓 `flip=true` → 失败（此时报 "Rib requires an existing solid body..."，因第一次失败已回滚掉底座，属于测试顺序问题，非工具缺陷）
3. 单独建底座（确认 has_solid=true）后单独 `creo_rib`（同一轮廓）→ 失败："Rib regeneration failed on the requested material side..."
4. `flip=true` → 同样失败

**分析**：
- native.log 显示两阶段创建正常（`ProFeatureWithoptionsCreate=0`、`created_feature_id=84`、MATRLSIDE 重定义成功），但 redefine 后 `ProFeatureStatusGet(&f, &status) != PRO_FEAT_ACTIVE` → 判定失败。
- 0.3.1 的 BUG-017 声称"修正原生筋材料侧设置顺序，验证开放相交剖面、flip 和厚度侧"，但在 Creo 9 上同样代码仍失败。**强烈怀疑与 Creo 版本相关**（Creo 12.4 验证通过、Creo 9.0 失败），可能是 `ProFeatureWithoptionsRedefine` 在旧版对 `PRO_E_STD_MATRLSIDE` 重定义路径的行为差异。
- 教科书式轮廓（底面中心竖直线、与实体相交、开放剖面）+ 两种材料侧全失败，可排除轮廓因素。

**建议**：
1. 在 RELEASE_NOTES 中为每个修复项标注**已验证的 Creo 版本范围**；对未验证的旧版（如 Creo 9/10）明确"不承诺"。
2. 若可行，在筋失败时输出 `ProFeatureStatusGet` 的具体状态码与 Creo 版本号，便于区分"环境不支持"与"轮廓不合法"。
3. 建议在 CI 中增加一个 Creo 9（或最旧支持版）的冒烟矩阵：筋、种子加载、dimension_pattern 三项。

### P1-1（行为变更/自动化回归）`creo_loft` 现在要求人工在 Creo 中注册并启动回调 DLL

**复现**：两个 XY 圆截面（Ø16@z25、Ø8@z45）直接 `creo_loft(sections=[la,lb], interpolation="smooth")` → 失败：

> `BLEND_CALLBACK_SETUP_REQUIRED: No DLL load or Blend creation was attempted. The unsigned Toolkit callback is not initialized, and Creo loader policy is prompt. ... Register and start the callback using Creo Auxiliary Applications and F:\...\blend_callback_setup.json (registry_file), review its DLL prompt yourself, then retry.`

**背景**：
- 0.3.0 上同样操作**直接成功**（本人 2026-10-15 测试记录：loft 体积 8639.38 精确对账）。
- 0.3.1 的 BUG-007 引入此机制：因 Creo 加载器策略为 prompt 且 MCP 不能代改安全设置，改为"建模前由人工在 Auxiliary Applications 注册并启动回调"。
- 注册文件（protk.dat）已生成在 build 目录，但启动必须由用户在 Creo UI 操作；`callback_result.json` 不存在说明回调从未启动过。

**影响**：`creo_loft` 与 `creo_new_airfoil_blade` 一样，从"开箱即用"变为"每次 Creo 会话需人工干预"。对无人值守自动化（MCP 的核心场景）是显著回归。错误信息本身写得很清楚（👍），但流程成本高。

**建议**：
1. 提供一次性持久化注册引导（注册后写入状态文件，`creo_loft` 调用时若检测到未启动，返回**当前会话是否已注册过**的明确状态而非直接失败）。
2. 评估对已签名的 callback DLL 的支持（消除 prompt）。
3. 在 `creo_startup_status`/`creo_session_status` 中暴露 "blend_callback: registered/started/missing" 状态，让调用方在建模前可探询。
4. 文档与错误信息中说明该状态的**生命周期**（每次 Creo 重启后是否需要重新启动）。

### P1-2（未修复）`component_constraints`：应用约束后元件位置不重新求解

**复现**：装入 comp2（fixed，平移 (-30,20,0)，绕 Z 30°）→ `creo_component_constraints` 应用 mate+align+align（三平面）→ 成功。
**结果**：约束正确挂接（引用/侧/类型均正确，`underconstrained=false`），**但 transform 仍是旧固定位置**，该位置实际违反新约束（30° 旋转下元件基准面与装配基准面不满足 mate/align）。

**建议**：`ProAsmcompConstraintsSet` 后触发装配重求解，或在返回中明确提示"约束已设置但需再生求解位置"。

### P2 其他观察

1. **`creo_shell` 在含镜像特征的模型上失败**（status 6，无具体原因提示）。模型：块体+孔+圆角+旋转体+镜像（关于 z=0）+变换+成组后 `shell(2mm)` 失败；回滚正常。同一流程在 0.3.0 测试时（镜像之前抽壳）成功。怀疑抽壳与镜像特征组合存在几何限制，建议失败时给出更具体的提示（如"unsupported geometry near MIRROR feature"）。
2. **失败的新模型无清理/恢复路径**：`wb_reg_pat`（我断言值写错导致失败）后模型进入 `status=failed, revision=0`，无法对其继续任何操作（"Model is not ready"），也没有删除/归档接口，只能弃用。建议提供 `creo_delete_model` 或允许失败模型重试。
3. **实体引用错误的报错仍会暴露巨大 union dump**（pydantic 校验错误含 60+ op 类型名），0.3.1 改进了部分提示但此场景依旧。
4. **`creo_hole` 对过期 surface id 的报错是 -23**（ProModelitemInit），提示不直观；建议 resolve 层对不存在/失效的几何 ID 给出"surface id N not found in current model, inspect and refresh"类错误。
5. **0.3.1 的查询分页（compact 默认）**：工作正常，`features` 等默认截断为摘要；建议在 `creo_inspect_model` 返回中始终带上 `truncated: true` 或 `complete: false` 标志，便于调用方（尤其跨版本客户端）判断。
