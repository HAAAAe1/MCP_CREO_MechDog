# MCP_CREO_MechDog v0.3.2 验收报告（对照 v0.3.1 缺陷清单回归测试）

- **日期**：2026-10-16
- **被测版本**：MCP_CREO_MechDog **v0.3.2**（`creo_capabilities.update`：current 0.3.2 = latest 0.3.2，"当前版本已是最高可比较的公开版本"）
- **验收方法**：针对上一轮（v0.3.1）报告的全部缺陷逐条做最小复现回归，用体积/边缘坐标/变换矩阵做客观判定

## 二、已修复项的验证细节

### P1 多区域增料 ✅
- 用例：100×100×10 底块 + 草图含 **2 个互不相邻矩形**（10..20 与 60..70）一次 `extrude(add, depth=20)`。
- 结果：成功，体积 **103 000 mm³** = 100 000（底块）+ 1 000（p1 高出部分）+ 2 000（p2 完整 10×10×20，位于底块之外）——逐项吻合。
- 意义：**百叶罩可由 2 次调用完成（原需 12 次）**、格栅筋条可一次成形，实体侧建模成本大幅下降。

### P2 共面合并 ✅
- 用例：10×10×10 方块草图放在 Z=10（正好是底块顶面），`extrude(add, depth=10)`。
- 结果：成功并入同一实体（`bodies:1`），体积精确 +1 000。
- 意义：铰链座/销、门板耳等"贴合式"特征不再需要人为制造咬合舌。

### P4 polyline ✅
- 用例：`{"type":"polyline","points":[4 点],"closed":true}` + `extrude(add)`。
- 结果：成功（+1 000 mm³ 精确）。
- 备注：`closed:false` 的开放链仍不能作为实体截面（这是合理行为），但失败时只报 "Regeneration produced a failed…"，建议补充"截面未闭合"这类可读原因。

### S9 `creo_list_components` ✅
- 现在 1 个组件返回约 4 KB 且**直接内联**（原 2 组件 170 KB 落盘）。
- 并且 `aliases` 现在带回**每个特征的草图几何、normal、u_axis/v_axis、section_normal_sign、solver 明细**——对定位挂接边、核对截面方向非常有用，值得肯定。

## 三、未修复项的复现细节

### S1 钣金件上增料 ❌（最高优先级）
- 用例：`acc_test_sm2`：底板 185×232×1（`sheetmetal_wall`，V=42 920 ✅）→ 草图 10×10 于 XY offset 0 → `extrude(mode="add", depth=5)`。
- 结果：`ProFeatureWithoptionsCreate failed with code -1 during execute_extrude`（op index 3）；同模型 `mode:"cut"` 正常。
- **这是钣金链路的头号阻塞**：钣金件上无法做任何实体增料（格栅筋条、凸台、铰链座/销、端壁、第二/三段折边框边全部做不了）。

### S3 封闭四壁盒 ❌
- 用例：同一底板，边 104/105/106/107 一次挂 4 道 `sheetmetal_flange`（h=80, R2.54, Y=0.5）。
- 结果：**前 2 道（±X）成功，第 3 道（−Y）失败**，`ProFeatureWithoptionsCreate -1`，整体回滚到只剩底板。
- 与 v0.3.1 完全一致；仍无折弯释放（bend relief）参数。

### S5 `depth=1` ❌
- 用例：`sheetmetal_wall(depth=1.0, thickness=232.0)`，草图线 185 长。
- 结果：体积 **9 957 440 = 185×232×232**（应为 185×232×1 = 42 920）。`depth` 被静默替换为 `thickness`。

### P5 旋转反手 ❌
- 用例：`assemble_component(rotation=[0,90,0])`，`creo_list_components` 回读 transform：
  ```
  [[0,0,-1],[0,1,0],[1,0,0]]  →  Ry(−90°)
  ```
  期望 Ry(+90°) = `[[0,0,1],[0,1,0],[-1,0,0]]`。**仍需传 [0,-90,0] 才能得到 +90°**，且工具不回显变换矩阵（需另调 `creo_list_components` 自查）。

### P3 dict plane offset≠0 ❌
- `{"kind":"datum_plane","axis":"x","offset":20}` → `Plane reference must identify exactly one surface`；
  补上 `{"reference":{...}}` 容器后**同样失败**。
- 即：**带 offset 的字典平面仍不可用**，仍需先用 `creo_datum_plane` 建面再按 label 引用。
- 正面：报错顺序改善——缺 `reference` 容器时会先给出明确的 JSON 错误（`key 'reference' not found`）。

## 四、建议（按收益排序）

1. **修 S1（钣金件增料）**：这是钣金链路唯一的硬阻塞。修复后，第二轮配电箱的格栅筋条/凸台/铰链/端壁可全部补齐。
2. **修 S3 + 提供折弯释放**：四壁开口箱是钣金最基本的形态；建议增加 `relief` 参数（矩形/扯裂/圆形）或自动角部处理。
3. **修 S5 并文档化 S4**：`depth`/`thickness`/草图线长三个方向请在工具描述中画清楚，并对被改写的参数返回告警。
4. **修 P5 并回显变换矩阵**：`assemble_component` 返回中直接带 4×4 transform，避免使用者必调 `creo_list_components` 自查。
5. **P3**：让 dict plane 的 `offset` 生效（自动建面），或在报错中直接提示"请先 `creo_datum_plane` 再按 label 引用"。
6. **P11**：`creo_export_model` 增加 `native_bundle`（.asm + C_*.prt 一起导出），或在文档中强调交付装配必须携带快照。
7. **S10**：计划失败时返回 `operation_outcomes`（已成功/失败清单），便于只重跑后半段。
