# 2026-10-15_CREO_0.3.0_旧版ToolkitSDK原生编译失败

> 反馈对象：MCP_CREO_MechDog 0.3.0（GitHub main 分支源码安装）
> 反馈人环境：Windows 10 x64 (19045) / Python 3.13.14 x64 / MSVC 19.44.35229 (VS2022 BuildTools 17.14) / Windows SDK 10.0.26100
> 目标 SDK：Creo Parametric **9.0.0.0** Pro/TOOLKIT（含头文件与 x64 链接库，setup.ps1 全部 9 项前置检查通过）
> 结果：打本地补丁后编译成功、MCP 服务冒烟测试通过；不打补丁则 `bridge.py build` 失败。

---

## 一、核心问题：原生代码硬引用 Creo 10 新增 Toolkit 常量，旧版 SDK 直接编译失败，且无版本防护

### 1. 现象

`setup.ps1` 前 6 个阶段（本机配置 / venv / client-config / 依赖 / 源码包 / 种子库）全部通过，最后一步原生编译失败：

```
INSTALL_INCOMPLETE: failed at SDK constants and native worker.
RuntimeError: Native build failed (2); see build\build.log
```

`build/build.log` 中的真实编译错误（其余均为无害的 C4819 编码警告）：

```text
native/geometry.cpp(104): error C2065: "PRO_E_HLE_ADD_PARAMETERS": 未声明的标识符
native/geometry.cpp(104): error C2065: "PRO_HOLE_NO_PARAMETERS_FLAG": 未声明的标识符
native/generic.cpp(179): error C2065: "PRO_E_HLE_ADD_PARAMETERS": 未声明的标识符
native/generic.cpp(179): error C2065: "PRO_HOLE_NO_PARAMETERS_FLAG": 未声明的标识符
```

### 2. 根因

- 两个常量位于 `ProHole.h`（孔特征元素树节点），为 **Creo 10 引入**，Creo 9 头文件中不存在。
- 引用点各只有一处，模式相同（创建孔特征时声明"不附加孔参数"）：

```cpp
// native/geometry.cpp  (hole 函数)
// native/generic.cpp   (generic_hole 函数)
integer(com, PRO_E_HLE_ADD_PARAMETERS, PRO_HOLE_NO_PARAMETERS_FLAG);
integer(com, PRO_E_HLE_ADD_NOTE, PRO_HOLE_NO_NOTE_FLAG);   // 此对常量 Creo 9 存在，无问题
```

- 值得注意的是：`tools/generate_constants.py` 在 Creo 9 SDK 上正常解析出 **6109 个常量名**并生成 `native/constants.inc`，说明除这一对外，其余代码与 Creo 9 SDK 兼容良好。
- 失败形态是裸的 C2065，用户无法直观判断是"SDK 版本不匹配"，需要逐条排查。

### 3. 本地临时补丁（已验证有效）

**补丁 1：`tools/generate_constants.py` 增加特性探测宏**——解析本机 SDK 后，按常量是否存在输出宏：

```python
# Constants absent from older supported SDKs (e.g. hole-parameter flags added in Creo 10).
PROBES = ('PRO_E_HLE_ADD_PARAMETERS', 'PRO_HOLE_NO_PARAMETERS_FLAG')

# generate() 中，在 tk_constants 定义之前追加：
lines += ['#define MECHDOG_HAS_' + n + ' 1' for n in sorted(names & set(PROBES))]
```

**补丁 2：两个调用点条件编译**：

```cpp
#ifdef MECHDOG_HAS_PRO_E_HLE_ADD_PARAMETERS
integer(com, PRO_E_HLE_ADD_PARAMETERS, PRO_HOLE_NO_PARAMETERS_FLAG);
#endif
```

补丁后 `bridge.py build` 一次性成功，产物：`build/creo_worker.exe`（8.7 MB）+ `build/creo_blend_sync.dll`（3.3 MB）；MCP stdio 冒烟测试：82 个工具全部注册，`creo_check_environment` 全部检查项通过（`ready_to_build: true`）。

语义影响评估：Creo 9 下仅跳过"不附加孔参数"这一元数据标志，孔的几何与定位元素不受影响；Creo 10/12 上宏存在，行为与当前代码完全一致（constants.inc 每次构建按本机 SDK 重新生成，源码指纹机制会正确触发重编译）。

### 4. 对作者的正式修复建议（按优先级）

1. **采用探测宏或运行时常量回退**：像上面那样在 `generate_constants.py` 输出 `MECHDOG_HAS_*` 宏是最小改动；或者给 `generic.cpp` 中已有的 `tk_constants` 查找加一个不抛异常的 `constant_opt(name)`（返回 -1 表示缺失），调用点判空后跳过。这样同一份源码可覆盖 Creo 9～12。
2. **在文档/兼容矩阵中明确"编译期最低 Toolkit API 级别"**，并在 `bridge.py build` 失败时识别 C2065 + PRO_ 常量名模式，直接提示"该常量需要 Creo 10+ SDK"，而不是把 C2065 留给用户解读。
3. 若决定继续只支持 10/12，也建议在 README 兼容矩阵处显式写明"SDK 早于 10 将在编译期失败"，管理预期。

## 二、次要问题与改进建议

### 1. INSTALL.md 未提示 VS Build Tools 需要 `--includeRecommended`（易静默装错）

实测（VS Installer 17.14 catalog）：`Microsoft.VisualStudio.Workload.VCTools` 的依赖里 **`Microsoft.VisualStudio.Component.VC.Tools.x86.x64` 与 Windows11SDK 组件均标记为 Recommended 而非 Required**（目录清单中无 Required 类型依赖）。只执行

```powershell
vs_buildtools.exe --add Microsoft.VisualStudio.Workload.VCTools --quiet --norestart --wait
```

会以**退出码 0 "成功"结束**，但编译器和 SDK 完全没有安装（安装日志中这些包 `PlannedAction: None`），后续 `bridge.py build` 才失败，且 `check_environment` 的 `compiler_setup`（vcvars64.bat 存在性）检查也可能通过，进一步掩盖问题。

建议在 INSTALL.md 与故障排查表中补充官方推荐命令：

```powershell
vs_buildtools.exe --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended --quiet --norestart --wait
```

### 2. `vcvars64.bat` 依赖 reg.exe 探测，受限环境下整条构建链不可用

在命令安全策略拦截 `reg.exe` 的环境（如 AI 代理沙箱），`build.cmd` 中的 `call vcvars64.bat` 无法完成 SDK 探测，即使 MSVC/SDK 文件完整。项目文档已提到"可传经审核的包装脚本"，但用户需要自己手写。建议官方内置一个不依赖注册表探测的轻量方案，例如：

- config.json 支持 `vcvars64_env`（显式 INCLUDE/LIB/PATH 的 JSON），`build.cmd` 直接 `set` 这些变量后进入编译；
- 或由 setup.ps1 在探测到 reg.exe 受限/失败时，自动生成包装脚本并回写 vcvars64 路径。

参考：本次实际使用的无注册表包装脚本只有 10 行（固定 MSVC 14.44 + SDK 10.0.26100 路径），配合 `compiler_preflight.py` 完整通过构建。

### 3. 小建议（可选）

- `setup.ps1` 的 Python 探测在只有"Microsoft Store 占位 python.exe"的机器上会以"Python was not found"失败；已有 `-Python` 参数兜底，建议探测到 WindowsApps 占位路径时在错误信息里直接提示"该 python.exe 是商店占位程序，请用 -Python 指定真实路径"。
- 原生编译失败时，`INSTALL_INCOMPLETE` 只给出日志路径；建议附加 `build.log` 末尾若干行错误摘要（本次反馈就是靠它定位的），可显著降低用户反馈成本。

## 三、明确不属于本项目问题的部分（供作者参考，无需处理）

以下均为本次安装环境自身的问题，与项目代码无关，且均已绕过：

1. 宿主沙箱同时注入大小写两份代理变量（`HTTPS_PROXY` 与 `https_proxy`），导致 VS 安装器 .NET 启动崩溃——`env -u` 绕过；
2. VS 安装器因系统存在待处理文件重命名操作而中断，留下半成品实例注册（表现为 install 报"已存在"、modify 报"找不到产品"）——清空 `_Instances` 后全新安装解决；
3. Toolkit SDK 与 Creo 本体未安装属用户前置条件，本次已由用户补装完成。
