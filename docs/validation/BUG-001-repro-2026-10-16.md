# BUG-001 现版本隔离复现(0.3.3)

日期:2026-10-16(Asia/Shanghai)。条目:[BUG-001](../work-items/BUG-001.md)、[DEV-030](../work-items/DEV-030.md) G0。性质:开发者隔离复现与恢复路径盘点,不是功能验收,不构成修复。

## 结论

**现版本 0.3.3 复现了履带报告第十七、十八节的阻断场景**(判定 a):

1. 保护层全部按设计工作且互相叠加——`unknown_outcome`、`pending_job` 保留、通道健康失效、模型级 `toolkit_busy` 拒绝(含 `blocking_*` 契约字段),但 **82 个公开工具中没有任何恢复、清锁、接受成果或协调接口**。
2. 保存前超时后,人工编辑 model.json 解锁(复现报告的手工步骤)会让 checkpointed 模型陷入**会话偏离门禁循环**:写操作反复失败于 "Saved feature/body count changed",自动回滚不触发,唯一出路是**真重启 Creo**(重启后从磁盘检查点恢复成功)。
3. 无 checkpoint 的新模型在同样处置下走另一条更危险的分支:下一次写操作**静默采纳脏会话状态**(半成品被存为新基线,revision 推进)。

按 DEV-030 G0 的进入条件,FEAT-018 受控恢复确认优先;修复设计输入见[任务卡](../work-items/FEAT-018.md)新增的 G0 输入节。

## 根因定位(0.3.3 源码,未修改)

`native/generic.cpp` 的 `run_generic`:载入已有模型时用 `verify_saved(model["inspection"], inspection())` 对照磁盘基线,检测到会话偏离即在**任何操作执行前**抛出;而 `mutated` 标志只在**本作业自己的写操作执行时**置位,失败后的 `rollback_to_saved_checkpoint` 分支要求 `connected && mutated && checkpoint` 三者同时成立——载入阶段失败时 `mutated=false`,回滚被跳过,脏会话模型原样留在 Creo 中,后续每次写入都重复同一失败。这解释了报告"持续失败、最终人工重启后续建成功"的全部现象。

## 启动事件(不计入 BUG-001 结论)

矩阵开始前:20:33 一次启动滞留(parametric 仅 25 MB、无 xtop 子进程;TEMP 同时刻存在 workbuddy-product-spill 条目,推测来自用户 WorkBuddy 会话)。清理后首次重试出现"外部程序 UNNAMED 没有正确初始化"弹窗并冻结(`toolkit_code=-11`、`worker_exit_code=20`);`creo_startup_status` retry 未能恢复,结束全部 PTC 进程并移除 0 字节 `toolkit.lock` 后一次冷启动成功。该现象属启动/通道家族(BUG-011、FEAT-001 边界),作为环境观察记录。
