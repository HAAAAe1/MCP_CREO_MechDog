# BUG-009 开发验证

日期：2026-10-15（Asia/Shanghai）。开发与本机 Creo 12.4 约定范围的验收已完成；末节补充 WorkBuddy 复核与未测边界。分支 `codex/bug-009-toolkit-busy`；源码基点 `88b0f51f3af225d9a79665f86405480c56fab4b8`，dirty=true。服务版本保持 0.3.1；本次没有发布或改写正式安装。逐文件受测指纹、原始响应、调用时间和报告 SHA256 见 [结构化证据](BUG-009.json)。

## 现象与根因边界

修改前使用两个真实 Windows 进程及真实 msvcrt 文件锁，受控替换 native worker 的结果，复现“查询 A 已成功，提交 C 仍 busy”。此用例验证调度时序，合成的 PRT/保存重载标志不算实际 Creo 证据。

| 本地时间（16:50:07，秒后小数） | 事件 |
| --- | --- |
| .734615 | A 已接受：job=df6643a0064b42f99bbc08fda391a55a，model=01e90058218845adbeb918f3cc02be1e |
| .741077 | 合成 worker 返回 |
| .743395 | A 写完模型登记；此时原代码已经释放通道 |
| .837347 | B 独立进程取得通道，A 尚未发布终态 |
| .839458 | 查询 A 返回 succeeded / revision=1 |
| .839458 | C 提交被拒，仅有 `Creo Toolkit is busy with another task; query its job and try later` |
| .851152 | B 释放通道 |

完整受控事件与原始响应保留在 `build/bug009-before.json`，并收入结构化证据。原实现的任务终态写入本就在锁释放之后，所以不能据此认定“原任务 succeeded 时仍持锁”。已确认的是模型收尾在锁外，以及其他调用占用时缺诊断；外部报告的全部历史根因仍未独立确认。

## 最终行为

单 Toolkit 通道继续使用即时拒绝策略。通用 runner 在锁内完成原生结果校验、revision/模型状态更新及 pending_job 收尾；退出锁后才发布持久化任务终态。后续调用若被另一个任务、提交登记、构建或连接探针占用，明确返回该次可观察的占用快照。元数据发布/删除窗口、旧客户端未写元数据或读失败时，ID 可以为 null，并说明无法确定；不能用最近一次成功任务冒充占用者。

busy 保持 MCP `isError=true`，JSON 文本与 `structuredContent` 一致，包含 `status=busy`、`accepted=false`、blocking_job_id / blocking_model_id / blocking_operation、owner_snapshot、retry_after_seconds 和 retry_guidance。此请求未创建新作业。已接受 job 只轮询；1 秒是重查间隔，非完成时间承诺；修改前重新读取 revision，unknown_outcome 先检查。pending_job 保护与快捷 plate 的拒绝也使用这套诊断。

已接受 runner 等锁预算仍为 120 秒，没有新增 FIFO 或公开队列容量保证。等锁超时不在另一个占用者的锁外写回模型，保留 reservation 与 recovery_required；compact 查询保留这些恢复字段。原生超时仍为 unknown_outcome，模型不是 ready，不能直接再次写入。文件写入失败继续保留原生结果，不以清除保护来恢复。占用元数据仅是诊断，互斥仍由操作系统文件锁保证。
