# FEAT-019：MCP 自动启动 Creo

类型：功能。优先级：P1。状态：开发中（实现与单元检查通过，实机启动链路仍在排查）。目标版本：未排期，当前服务版本 0.2.5。

建立日期：2026-10-13。来源：用户要求“先做 MCP 自动开启 Creo”；关联 [统一台账](../BACKLOG.md)、FEAT-001 会话检测、FEAT-002 人工等待状态。BUG-002 已完成，本条目安排在 DEV-002 布局迁移之前。

## 目标与当前行为

用户启动 MCP 服务后，服务自动检测本机 Creo 会话：已有可复用会话则连接；没有会话时启动已配置的 Creo，并等待 Toolkit 实际可连接，使用户可以继续建模。

目前 [bridge.py](../../bridge.py) 的 `session_status` 连接已有会话，本机配置含 `creo_root` 和可选 `creo_session_id`；本条目新增启动与就绪管理。进程出现、启动命令返回或前置文件检查通过，均不足以证明建模链路可用。

## 首批范围

- MCP 服务启动时执行检测与按需启动，提供自动启动开关及有界等待配置；开关名称、默认值和超时预算在设计阶段明确并记录。
- 使用当前机器的 Creo 安装与配置启动；核对真实启动入口、参数、必要环境和返回行为，支持含空格路径，不把开发机绝对路径写入源码。
- 复用已有符合选择规则的会话；对指定 `creo_session_id`、失效 ID、正在启动及多个会话分别定义处理方式，不猜测应连接的目标。
- 启动请求进行协调，避免服务初始化与多个客户端请求同时重复启动；跨 MCP 服务进程的并发场景也需验证。
- 以实际 Toolkit 连接确认就绪。等待期间明确状态，建模请求仅在就绪后正常执行，或返回清楚的未就绪原因；初始化不能无限阻塞 MCP 协议响应。
- 配置错误、启动失败、超时和需要人工确认的情形保留诊断与重试入口；复查启动进程与会话的实际状态后再决定是否再次启动。
- 不自动关闭用户已有会话或接管未保存模型。自动启动关闭时继续支持用户手动打开 Creo 后连接。

本条目首先建立启动闭环；FEAT-001 的完整会话检测、FEAT-002 的通用人工等待以及 BUG-001 的失联任务恢复保持各自范围，不能因本功能通过就一并标记完成。

## 设计前必须确认的事实

1. 当前安装的真实启动程序/脚本与参数，Windows 用户会话和 MCP 子进程启动条件。
2. 启动进程与 Toolkit 会话的对应关系、启动耗时及可用的会话选择信息。
3. 已有连接函数的重试/超时行为，MCP 初始化和请求并发边界。
4. 多会话与指定会话规则、重启后的 ID 变化、启动失败后的现场状态。

2026-10-13 核对结果：当前 Creo 12.4 的 parametric.bat 实际调用安装目录 Parametric/bin/parametric.exe 并显式传入 parametric.psf。最终实现通过已核对用户及 Windows 会话的 Explorer 桌面启动接口传入 exe + PSF，PSF 用 Windows 参数编码，不拼接 cmd 命令；GUI 继承桌面环境并使用自身 PSF 运行环境，Toolkit 通信库和 PRO_COMM_MSG_EXE 只用于原生 worker。必要 Windows 环境变量从当前用户环境补齐，许可值不进入诊断。首次核对时没有运行中的 Creo 进程，可用于冷启动验证。

Toolkit 的 ProEngineerConnect 禁止随机选择时会返回多会话歧义；指定 ID 连接失败可能回退，因此现有 connect_creo 会核对实际 ID 并拒绝错连。保留该保护，不自动替换用户指定的失效 ID。现有 status 探测连接等待为 30 秒，首批增加可指定的短连接等待和明确连接结果分类，建模连接契约保持原样。

本分支为 codex/feat-019-creo-autostart，从包含已验收 BUG-002 / DEV-010 的 0702029 承接开发规范与登记修复；远端 main 尚未包含这些依赖，交付时明确基线。

### 首批配置与状态契约

- auto_start_creo：布尔值，缺省 true；false 仅检测/等待用户手动打开，不自动启动。
- creo_startup_timeout_seconds：整数，10～600，缺省 120；原生准备/构建阶段另受现有构建超时约束，后台初始化不阻塞 MCP 握手。
- creo_startup_psf：可选绝对 .psf 路径；缺省为配置安装目录下 Parametric/bin/parametric.psf。启动入口固定取该安装的 parametric.exe。
- 状态为 checking / building_worker / starting / waiting_for_connection / ready / disabled / selection_required / configuration_error / launch_failed / timeout；仅实际 Toolkit connected 为 true 可进入 ready。公开工具返回状态、原因与是否允许重试，不返回敏感会话 ID 或许可值。
- 相同 Windows 用户会话、安装及 PSF 使用 LocalAppData 下的同一启动锁与状态；跨 MCP 进程共享。锁保护预留、实际启动及就绪等待，后来的请求只等待/读取状态；leader 失联后先检查真实进程及既有预留，不直接重启。
- 可复用的已有会话不启动；正在启动或进程仍在但 Toolkit 不可连接时只等待，超时提示检查人工确认/启动环境。多会话未指定目标时要求选择；指定 ID 不可连接时不启动替代实例。其他安装/无法确认的进程状态不猜测目标。
- 新增 creo_startup_status(retry=false)；retry=true 请求后台复查并仅在确认没有现存/启动中进程、没有有效预留后再次启动。初始化及重试均不自动关闭任何 Creo 会话。
- 服务 lifespan 触发后台初始化，建模入队前检查就绪状态；creo_session_status 继续提供真实连接检查，并关联启动状态。

## 验收标准

| 场景 | 预期结果 |
| --- | --- |
| Creo 未运行、自动启动开启 | 启动 MCP 后按配置启动 Creo，预算内取得真实 Toolkit 连接；用户无需先手动启动 Creo |
| 已有可复用会话 | 连接或复用目标会话，不重复启动新实例，原有模型和工作保留 |
| 多个启动请求、多个 MCP 进程 | 同时请求受到协调；对同一启动目标不重复拉起，等待者获得一致的启动/就绪结果 |
| Creo 正在启动 | 继续等待或返回启动中状态；不会因暂时无法连接而不断拉起新实例 |
| 多会话、指定或失效 ID | 按已记录规则连接、拒绝或提示选择；不得静默连接错误会话 |
| 自动启动关闭 | 不自动拉起；用户手动打开 Creo 后重新检测并正常连接 |
| 错误路径、启动失败、持续无法连接 | 有界失败，返回有依据的原因与后续操作；不能仅凭一个 Toolkit 错误码断言许可或版本原因 |
| 人工确认或加载等待 | 明确等待或超时情况，保留上下文；不声称已经就绪或反复启动 |
| 启动后的端到端建模 | 新建独立小零件，完成草图/拉伸、几何或体积断言、参数编辑及保存重载；任务成功且 `saved_file_reloaded_and_verified == true` |
| 日志与协议 | stdout 保持 MCP 协议用途，启动诊断可追踪且不暴露许可值或完整敏感配置 |

## 验证分工与证据

开发者通过 Windows 单元测试和受控进程/连接替身验证配置、状态转换、超时与并发协调，再在真实 Creo 环境验证启动、连接和建模；单元检查不能替代真实启动。配置和能力变化同步工具说明、安装文档及有关回归。

按 [开发入口](../DEVELOPMENT.md#workbuddy-测试约定) 进行 WorkBuddy 最终验收：由用户或开发者准备初始软件状态和配置，WorkBuddy 直接调用公开 MCP 工具，核对连接、等待/错误反馈及建模结果。不要求 WorkBuddy 看源码、读取配置或运行本地脚本；公开接口无法确认的启动次数、进程身份和内部协调记为未验证。

正式验收基线为 Creo 10，其他版本按 [兼容矩阵](../COMPATIBILITY.md) 分别记录。新证据注明源码提交/dirty/指纹、环境、初始会话状态、实际启动/连接时间、工具输入返回、job_id/model_id、终态与几何/保存重载结果。完成后关联仓库内验收摘要并更新台账。
