## 问题与目标

报告观察回调副本目录和命令含 DLL SHA256，0.3.0→0.3.1 的 DLL 改变后注册路径改变，推测需反复注册。反馈方从未成功注册过，升级后失效、同名冲突和重新注册成本尚未实测，不能登记成已确认故障。

2026-10-16 只读源码核对：`src/creo_mechdog/blend_callback.py` 已生成固定名称的 `build/blend_callback.protk.dat` 快捷入口，但其 `exec_file`、`text_dir` 指向 SHA256 目录，派生命令还包含 DLL 哈希及安装根目录标识。当前查询只说明产物是否准备好；`native/blend_create.cpp` 在建模时检查初始化记录、协议、命令及实际 DLL 句柄。这些是实现事实，不是本次实机复现结论。

预期行为：首次正式注册后，已验证兼容的升级尽量沿用原注册；需要启动回调、重启 Creo 或重新注册时，调用方在建模前即可查到实际原因和具体操作。验收分别记录“是否重新注册”“是否手动启动”“是否重启 Creo”，免重复注册不等于免重启。

## 范围与方案约束

1. **生命周期核实与升级方案。** 覆盖首次注册、启动、Creo 重启、同一安装根目录升级、旧模块仍加载、回退及不同目录并存；比较稳定注册入口、稳定回调模块或经过验证的兼容复用与不可变版本产物等方案，再选择最小完整实现。稳定 `current` 路径仅为候选；固定注册文件名、同一服务版本或相同 `protocol` 都不能直接证明 DLL、命令及资源兼容。不得直接覆盖或删除仍加载的 DLL。
2. **运行就绪预检。** 通过现有公开状态接口或明确的只读查询入口，区分产物状态与当前会话实际加载/兼容状态；至少表达就绪、未加载、版本不匹配和无法确认，并提供原因、可验证身份、探测时间及下一步。具体接口、字段和等待预算在选型阶段确定，保留现有调用兼容；会话不可达、繁忙或探测超时不得误报未注册/已就绪，旧记录不得作为新会话已加载的证明。
3. **升级与失败提示。** 按可验证状态区分只需启动回调、需重启 Creo、需重新注册、不兼容及无法确认，附当前正确注册入口；无法由 MCP 证明 GUI 注册状态时据实说明。配套更新能力说明、安装/迁移指引及该版本升级说明。
4. **身份、回滚与并存保护。** 分别识别当前部署产物、当前服务实例和实际会话模块；跨安装目录不得误复用命令或资源，不因旧 DLL/旧初始化文件存在而报就绪。升级失败保留可恢复旧产物和清晰处置，不擅自卸载模块、重启 Creo、清理未知任务或自动重交 `unknown_outcome`。
5. **建模回归。** 覆盖 `creo_loft` 和 `creo_execute_plan` 的 loft 入口，确认原生 Blend、已有特征身份、几何、revision、失败回滚及保存重载；原种子放样作针对性对照。

本卡承接 FEAT-008 的回调就绪预检，其余能力契约仍归原项；FEAT-022 的通用 MCP 陈旧实例提示保持原排期，本卡只处理生命周期判定必需的身份比较。放样 cut/surface/非平行截面扩展、种子降级替代、全量能力文档重构和通道自愈不纳入本项。

建模和查询不自动加载 DLL、不修改 Creo 安全策略；首次及必要的 GUI 注册/启动、安全提示确认由测试发起者按正式流程完成。兼容升级免重复注册是优先验收目标；若调查证明某分支无法达到，须提交实测限制、剩余人工步骤和未完成范围，不能自动降为“只做预检与提示”后关闭。
