# BUG-055：恢复 apply 的 MCP 可空参数与 stale 拒绝差异

日期：2026-10-17。类型：缺陷。优先级：P1。状态：待核实。目标版本：未排期。

来源：[0.3.4 / Creo 9 反馈补录](../validation/FEEDBACK-0.3.4-2026-10-17.md)第二节；[原件](../validation/feedback-0.3.4-2026-10-17/creo9-recovery-callback-report.md)。关联 [FEAT-018](FEAT-018.md)、FEAT-008、DEV-006/007。BUG-001 按用户决定关闭，本项单独跟踪新工具的调用路径差异，不据报告重开历史卡死/协调缺口。

## 报告现象与待核实根因

外部 Windows 10 / Creo 9.0.0.0 / stdio / 服务 0.3.4、84 工具：历史失败模型 `wb_reg_pat`，status=failed、revision=0、baseline=null；`creo_reconcile_model` inspect 正确返回原作业/所有者检查、可用动作、evidence_token 及 600 秒有效期，仅 abandon_new 可用。

报告称 MCP apply 传 `expected_revision=0, expected_pending_job_id=null`，被 `Stale expected_revision or expected_pending_job_id` 拒绝；本地 Python 直连再手动驱动作业到 succeeded，模型变 abandoned。`pending=None` 与 `pending=''` 的本地校验对照分别通过/拒绝。报告没有提供完整 MCP request/response、工具 schema、job_id/model_id、同次 inspect/apply token 和状态时间线。

这支持调用路径存在差异的线索，尚不能证明 JSON null 在服务端或客户端被转成空字符串，也不能排除字段被省略、包装默认值或证据在两次调用之间失效。报告的本地 Python 路径不是 MCP apply 验收；单例不能证明所有动作或“绝大多数模型”均受影响。本机没有重新复现。

报告原列 P0；当前按 P1 待核实登记：已有标准恢复路径受阻线索，但未取得全通道封锁或会话损坏证据，优先级随当前复现与影响范围复核，不直接采纳“一行修复即可”的实现结论。

## 范围与核实顺序

1. 先离线核对公开可空 schema、MCP 注册函数/默认值、适配与 reconciliation 比较路径，并保留现有 revision、pending_job、证据令牌和所有者保护。
2. 开发者用真实 stdio MCP / FastMCP 传输和受控协调夹具，对照显式 null、省略、空串、字面字符串 `"null"`、正确/错误非空 ID，记录请求原始形状及各层实际值；夹具不连接 Toolkit，内部机制证据单独标识。
3. 保持 inspect 到 apply 之间 revision/pending/所有者及 token 未变，在反馈客户端与独立客户端对照。若客户端不能发送 null，记录客户端限制与准确指引，不伪称标准 null 已在服务端复现。
4. 确认转换位置和兼容范围后再修复。不得使用广泛 truthiness 归一化吞掉错误 ID、过期证据或必填字段缺失；是否接受空串需明确选型，不能自动当作协议标准。

本项不延长 token 或自动应用过期授权；证据时效体验归 FEAT-018。真实恢复验证继续受 [本机联调约束](../../AGENTS.md#本机开发联调补充2026-10-17用户要求)，不杀 Creo、不清 pending/unknown、不自动重放历史作业。新 Python 业务逻辑放入包内，MCP 入口只承担注册与适配职责。

## 验收标准

| 环境 / 场景 | 可判断的预期结果 |
| --- | --- |
| Windows / 真实 MCP 协议回归 | schema、显式 null 与适配后值一致；省略/空串/字面 null 按确定契约准确拒绝或兼容，不误报为模型真的发生 revision 冲突；针对性回归与统一开发检查通过 |
| stale 与授权保护 | revision、pending_job、token 或所有者确有变化时仍拒绝，模型和原作业保持原状态；空值修复不能放宽证据校验或自动重试 |
| 无基线自有测试件 | inspect 返回的可用动作、token、expected_revision/pending 原样经 MCP apply；abandon_new 成功后模型状态、历史审计、revision 和重复请求行为符合正式契约 |
| 其他受影响分支 | 有真实非空 pending 的合法/非法对照；四种动作按适用模型分别记录，未执行动作明确未验证，不能用 abandon_new 推断全部恢复通过 |
| WorkBuddy 黑盒 | 测试发起者预置自有测试模型，WorkBuddy 仅 MCP inspect→人工选择动作→apply→轮询；记录原始输入/错误、job/model、终态、revision、审计及适用保存重载，不读源码/配置或绕过 MCP 执行 Python |
