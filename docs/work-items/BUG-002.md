## 问题与目标

任务执行进程写入 `job.json` 或 `model.json` 时，客户端同时轮询读取；JSON 临时文件替换可能遭 Windows 拒绝访问，导致进度或终态未可靠保存、任务提前失败，或模型登记更新不完整。

预期：短暂读写竞争下，读者获得完整的旧版或新版 JSON，登记写入在有界时间内完成；持续失败应保留最后有效文件并明确报错。保持原子替换、revision 防护和已存在的任务结果判定。

### 已有证据与本次核对

| 来源 | 已知事实 | 证据边界 |
| --- | --- | --- |
| 原报告 P1-06 | 一次 `creo_group_features` 任务替换 `job.json.<uuid>.tmp` 时 WinError 5，任务目录没有 native.log/worker.log | 原生执行前发生，不能据此判为 Creo 分组几何失败；实际占用句柄的进程未追踪 |
| 原探针及 JSON，2026-10-13 | 串行 100 次、0 失败；3 个读线程期间写入 400 次，成功 4 次、失败 396 次，全部 WinError 5；读取 9861 次，读取错误 14 次 | 本轮读取并核对了既有统计，未重新执行；高频压力结果不代表日常轮询失败率，也不等于当前分支验收 |
| 当前源码静态核对 | `bridge.read_json` 使用 `Path.read_text`；`write_json` 写 UUID 临时文件后直接 `os.replace`，未实现重试或失败临时文件清理 | 支持进一步检查 Windows 句柄共享与短暂占用，不足以单独确定所有拒绝访问的根因 |

当前分支核实：2026-10-13 隔离探针对 job.json 和 model.json 各执行 5 轮 × 400 写入，共 4,000 次写入中 3,978 次失败（WinError 5），读取错误 79 次；串行均通过，固定普通读句柄稳定阻止替换，释放后可写。清理前遗留 3,982 个临时文件。完整修复前证据保存在 build/BUG-002-reproduction.json，随后关闭句柄并删除夹具。

确认根因：普通 CRT 读句柄不共享删除访问；此外，本机 NTFS 上 MoveFileEx（os.replace）仍拒绝替换持有共享删除句柄的目标。Windows 读取改用 FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE，替换使用 SetFileInformationByHandle(FileRenameInfoEx, REPLACE_IF_EXISTS | POSIX_SEMANTICS) 单步重命名，保证旧句柄继续读取旧版本。系统/文件系统明确不支持扩展接口（1/50/87）时回退原子 os.replace；不先删除目标，不使用失败可能移除目标的 ReplaceFileW。

替换阶段仅对 Windows 错误 5/32/33 在 1 秒预算内指数退避（5 ms 起，最多 50 ms，最多 25 次尝试）；错误 5 也可能是 ACL 拒绝，不能宣称全部为竞争，识别只读目标后立即传播，其他持续拒绝有界报错。临时文件创建/写入和读取异常不重试。独占创建 UUID 临时文件，写完关闭后替换；失败只清理本次已创建文件，清理再失败时保留主异常并附诊断。

## 复现步骤

所有探针导入当前仓库的 `bridge`；外部原探针硬编码另一安装目录，不能原样运行作为本分支证据。使用仓库 `.tmp/` 下新建、校验路径后的独立夹具，只写夹具内 JSON；记录结果到 `build/BUG-002-reproduction.json`。完成前保留失败统计与临时文件数量，随后关闭线程和句柄再清理夹具。

1. 记录 Windows/Python、提交、dirty 标志和当前 `bridge.py` 内容 SHA256，创建初始 `state.json`，使用固定字段和递增序号。
2. **串行对照**：连续调用 `write_json` 100 次，每次读回并比较完整内容；记录错误、最终值及遗留临时文件数。
3. **并发对照**：3 个读线程持续调用 `read_json`；一个写线程按原探针规模写 400 次。记录写成功/失败、读取成功/错误、异常类型、winerror、耗时和最后有效序号。读者校验字段及数据完整性，不只统计 JSON 能否解析。
4. **固定占用对照**：用事件同步控制目标文件读句柄的存活，保持约 200 ms 后释放；分别检查占用期间与释放后的写入结果。必须确认冲突确实触发，否则该用例只能记为未复现，不能视作重试已验收。
5. **持续失败对照**：固定占用超过拟定写入预算，另用可控错误注入验证不可重试错误；核对失败传播、旧文件内容、目标是否曾缺失及本次临时文件清理。
6. 对 `job.json` 和 `model.json` 夹具重复读写场景；至少执行 5 轮并发对照。修复前保存失败证据，修复后使用相同参数比较，不要求复制历史 396/400 的具体失败比例。

若随机压力未触发问题，继续固定占用用例与路径/文件系统差异排查；记录“未复现”及尝试条件，不直接进入已完成。根因和稳定回归明确后，将台账更新为待开发，再实施修复。

## 修复原则与验收标准

实现阶段先给出重试错误范围、退避与总预算，建议短暂占用恢复用例在 2 秒内结束。不得无限循环；不可重试错误尽快传播。重试用例必须证明经历失败后成功，避免只测未触发竞争的顺畅写入。

| 环境 / 用例 | 可判断的验收结果 |
| --- | --- |
| Windows/Python，串行 | 100 次读写全部成功，内容正确，无遗留本次 `.tmp` 文件 |
| Windows/Python，并发 | 3 个读线程 × 400 次写入 × 5 轮；写入与读取错误为 0，无空文件、半截 JSON、字段损坏或读取期间目标缺失；每轮最终内容为最后一次成功写入 |
| 短暂占用、可控失败 | 释放后在预算内成功；确认重试路径实际执行、重试次数有界，临时文件清理；旧版/新版均完整 |
| 持续占用、不可重试、写临时文件失败 | 明确失败，不返回成功；旧目标字节内容保留，无先删目标行为；清理仅限本次创建文件，不删除其他写者文件 |
| 兼容与读取异常 | 中文和 BOM 可读；缺失文件、无效 JSON、权限/其他 I/O 错误不被无限重试或转换成空对象 |
| 任务与模型登记回归 | 入队、进度、终态可靠落盘，持续轮询可读；成功修改 revision 只增加一次，失败/只读不虚增；完成后的 pending_job 和终态与原有成功/失败/未知结果语义一致 |
| 终态落盘失败 | 保留已取得的原生结果与最后有效登记，错误原因可从现有日志追踪；不伪造成功，不仅凭文件冲突报告几何失败，不自动重复原生操作 |
| 统一检查 | `tools/dev_check.py --work-item BUG-002` 通过；针对性用例 tests_run > 0；新增测试不依赖 Creo，以 Windows CI 执行 |
| 本机 Creo 12.4 / 匹配 SDK，真实任务轮询 | 独立夹具上执行新建及一次成功修改，并发轮询任务与模型；任务成功、原生几何/参数断言通过、saved_file_reloaded_and_verified 为 true、revision 正确且 pending_job 清除；失败回滚及 stale revision 用例通过 |
