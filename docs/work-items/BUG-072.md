# BUG-072：非毫米接管预检误标单位与体积

日期：2026-10-19。类型：缺陷。优先级：P2。状态：验收中。目标版本：未排期。

来源：用户转贴WorkBuddy的WB_REJECT_INCH公开MCP验收，见[补录](../validation/ADOPTION-WorkBuddy-2026-10-19.md)。关联FEAT-042、FEAT-008。

## 已证实现象与定位

本机Creo12.4 UI通过inlbs_part_solid_abs创建1×1×1英寸立方体，体积工具实测1.00000 in³，保存为外部wb_reject_inch.prt.1。公开adopt inspect正确返回available=false、millimeter_units=false及毫米单位拒绝，不提供登记ID/令牌；同一返回却包含inspection.units="mm"、两层volume_mm3约1.0。模型准入保护通过，拒绝载荷的量纲与体积字段错误。

开发者静态核对native/generic.cpp：inspection()固定写units="mm"，将ProSolidMassPropertyWithDensityGet的mp.volume直接赋给volume_mm3；adopt_current_native另调用millimeter_units(board)作为准入判断，随后把前述inspection嵌入live。不是已经证实的会话/全局单位读取，不能沿用报告中的该根因猜测。SDK体积的单位契约仍应在实际实现时结合匹配SDK核对；本轮UI与公开值已足以证明现有载荷误标。

## 范围

- 使非毫米/未知单位的只读来源摘要诚实反映单位和体积，不再把原生1 in³标为1 mm³；无法可靠换算的毫米量返回null，若实施换算须同时证明单位因子及相关长度/面积/体积字段含义。
- 核对current_model及嵌套inspection的一致性，以及准备证据/摘要裁剪/续签路径；现有毫米模型数值与哈希证据的兼容范围应明确。
- 保留只接管毫米模型、独立健康来源及证据/版本/通道保护，不借此新增非毫米建模支持。
- 装配工具级错误与非毫米结构化拒绝的格式差异归FEAT-008，单独评估兼容方式，不以修量纲为由放宽拒绝。

## 当前状态

已实现原生长度单位查询、units_query_code及诚实的毫米体积投影：只有确认mm且体积有限时填写volume_mm3，英寸/其他单位或单位未知返回null，不进行未经验证的换算；坐标等仍按inspection.units所示的模型长度单位。接管准入复用同次单位证据，继续拒绝非毫米/未知来源。摘要保留单位查询诊断，新增头文件进入启动指纹清单。与FEAT-042的prepare顶层adopted=false修正同时完成，相关真实stdio隔离回归与8例匹配SDK声明的C++隔离用例通过；执行器匹配12.4 SDK构建通过。完整检查、源码身份和限制续记于[接管补录](../validation/ADOPTION-WorkBuddy-2026-10-19.md)。
