# FEAT-020：版本更新检查与提醒

建立日期：2026-10-14。

类型：功能。优先级：P2。状态：验收中。目标版本：0.3.0（新增功能递增 MINOR）；开发源码暂沿用 0.2.6，验收后按 [发布规则](../development/RELEASING.md) 同步版本并发布，尚未发布。

来源：用户要求将版本更新检查与提醒方案写入文档并创建任务卡。统一入口为 [开发台账](../BACKLOG.md)；兼容性说明沿用 [兼容矩阵](../COMPATIBILITY.md)。

## 问题与目标

当前服务通过 `version.py` 和 `creo_capabilities` 提供本地版本，但不会查询 GitHub 发布版本，也没有面向用户的更新提醒。用户可能继续使用旧版而不知道新版已发布。

目标是在 MCP 中检查可更新版本，并通过工具结果向 AI 客户端提供当前版本、新版本、下载入口和版本说明入口，由客户端提醒用户按现有安装流程手动更新。项目当前使用 Pre-release 发布，检查必须包含已公开的预发布版本。

2026-10-14 初始任务卡仅登记计划；本次已实现接口并执行开发者回归，实际结果与未测范围见末尾。

## 范围与接口

1. 查询 `wudahua/MCP_CREO_MechDog` 的 GitHub 公开 Release 列表，包含正式版及 Pre-release，排除草稿和未发布内容；不使用只返回正式版的 `/releases/latest` 作为唯一来源。处理分页，不以列表第一项或发布时间直接判断版本大小。
2. 以 `version.py` 的 `VERSION` 为本地版本入口，按语义版本比较；兼容 `v` 标签前缀和项目候选版格式。相同或更低版本不提示更新，开发版高于公开版本时不建议降级。历史不规范标签不参与比较，全部候选都无法解析时返回无法确认，不能宣称已是最新版。
3. 增加后台异步检查和缓存，避免联网阻塞启动、能力查询、启动状态查询或建模。建议初始检查缓存有效期为 24 小时、网络超时为 5 秒；实现时明确实际参数及超时边界，失败后避免高频重试。
4. 新增只读工具 `creo_check_update(force=false)`：默认使用有效缓存，`force=true` 请求重新检查；该工具不下载、安装或修改源码、配置、模型与任务。联网访问的工具注解按实际外部访问行为声明。
5. `creo_capabilities` 和 `creo_startup_status` 增加同一结构的 `update` 字段，读取缓存快照，不同步等待 GitHub 请求；保留现有字段和启动就绪、revision 等契约。
6. 服务 instructions 引导 AI 客户端首次使用时检查更新状态；发现新版本时告知用户，同一会话对同一版本避免反复提醒。MCP 提供提醒数据，实际展示由客户端执行，不承诺所有客户端均有弹窗。服务 stdout 继续只承载 MCP 协议消息。

`update` 建议包含下列字段；实施时在工具描述和回归测试中固定最终契约：

| 字段 | 用途 |
| --- | --- |
| `status` | 区分尚未检查、检查中、有更新、已是最新版、检查失败或无法确认 |
| `current_version` | 当前运行的服务版本 |
| `latest_version` | 最近一次成功检查得到的可比较最高公开版本；无法确认时为 null |
| `is_prerelease` | 目标 Release 是否标记为 Pre-release |
| `release_url` | 目标版本的 GitHub 发布说明页面 |
| `download_url` | 对应版本的官方源码附件链接；无可识别附件时指向 Release 页面作为下载入口 |
| `checked_at` / `from_cache` / `stale` | 标明检查时间、是否使用缓存以及信息是否过期 |
| `message` / `error` | 可转述的提醒及检查失败原因；不包含凭据或本机敏感配置 |

网络断开、超时、限流、非预期响应或数据解析失败只影响更新检查，不阻止 Creo 就绪或建模。失败时不能返回“已是最新版”；若展示上次成功检查结果，必须标明缓存过期及本次检查失败。

## 用户提示与升级流程

提示示例（版本号仅用于说明，不代表已排期或已发布）：

> MCP_CREO_MechDog 有新版本可更新：当前 0.2.6，新版 0.2.7（预发布）。请查看版本说明和下载链接。等待建模任务完成，停止 MCP 服务，保留本机配置、模型和任务记录，更新源码并重新运行安装脚本，然后重启 MCP 服务。

升级步骤沿用 [安装说明](../INSTALL.md) 与 [迁移说明](../MIGRATION.md)，使用目标 Creo 对应的 SDK 重新构建。提醒功能不自动执行升级、不强制中止建模，也不自动关闭 Creo。

旧版本必须先手动升级一次到包含 FEAT-020 的版本，后续才能通过 MCP 收到更新提醒。发布说明须明确这一前提，不能声称未安装此功能的旧版本也能主动提醒。

## 开发步骤

1. 按本任务卡实施版本检查、语义版本比较、缓存及非阻塞失败处理。
2. 注册 `creo_check_update`，在能力查询、启动状态和服务 instructions 中接入提醒数据；同步工具数量、能力文档和安装说明。
3. 执行四类核心回归与缓存、候选版排序、非法标签等必要边界测试，完成适用开发检查和 MCP 验收。
4. 按发布规则同步版本、说明、打包、校验和及 GitHub 新 Release；继续包含 Pre-release 的检查方式，保持已发布标签和同名附件不变。
5. 用户先升级一次；以后发布更高版本时，安装了此功能的 MCP 能返回更新信息。

## 验收标准

开发测试环境为 Windows x64 / Python 3.12+。版本与网络分支用受控响应进行确定性回归；实际 GitHub 联网检查另记结果。用户于 2026-10-14 明确分工：本机只验证 Creo 12，Creo 10 由协助者在其他机器验证，不等待本机具备 Creo 10。MCP 验收仍分别记录两种环境的实际版本及范围；已记录的 Creo 12 环境为 12.4.0.0。若无法取得某环境，明确记为未验证，不能复用历史成功作为本项通过。

| 环境 / 用例 | 操作 | 可判断的预期结果 |
| --- | --- | --- |
| 有新版本 | 本地版本低于已公开 Release，调用更新检查工具 | 返回当前与更高版本、下载与版本说明链接，提示可更新 |
| 已是最新版 | 本地版本与最高有效公开版本相同 | 返回已是最新版，不提示升级；本地高于公开版时不建议降级 |
| Pre-release | 发布列表只有预发布版本，或最高候选是预发布版本 | 能发现更高的公开预发布版本，并明确标识；候选版与正式版按语义版本正确排序 |
| 网络失败 | 受控断网、超时或限流后调用检查 | 返回检查失败或无法确认；能力查询、启动状态和建模不被联网检查阻塞，不把失败当成已是最新版 |
| 缓存与接口一致性 | 连续查询三个接口，必要时主动刷新 | 有效缓存复用；三个接口结构与来源一致；刷新过程中已有接口及时返回，过期结果有明确标识 |
| 无有效发布数据 | 返回空列表、草稿或无法解析的标签 | 无草稿提醒、无无效版本比较、无虚假的“已是最新版”结论 |
| Windows 开发检查 | `tools/dev_check.py --work-item FEAT-020` 及针对性回归 | 无新增语言问题、适用单元测试通过，保留本次报告 |
| Creo 10 / 12 MCP 实测 | 查询能力、启动状态、更新状态；网络失败场景下完成小零件建模 | 保留服务和 Creo 版本、输入返回、job_id/model_id、终态、几何及保存重载结果；失败的更新检查不影响正常建模，分别记录两种 Creo 环境 |
| 发布 | 按发布规则制作新版本并检查真实 Release 与安装后的 MCP | 服务版本、工具列表与发布说明一致，附件和校验和有效；具备 FEAT-020 的旧安装能发现后续更高版本 |

本功能不修改原生建模实现；Creo 实测用于验证联网检查与原有启动、建模的集成关系，不宣称重新覆盖全部原生特征。

WorkBuddy 最终验收仅通过已连接 MCP 的公开工具检查用户可见行为，不查看源码、不运行本地 Python 脚本。外部发布数据和断网条件由测试发起者准备；无法通过 MCP 实际观察或实施的场景记为未验证。缓存时长、重试次数等内部机制由开发者测试记录，不由 WorkBuddy 推测通过。开发测试与最终 MCP 验收分别归档，按 [开发入口](../DEVELOPMENT.md#workbuddy-测试约定) 执行。
