# BUG-008：原生收尾挂死、Toolkit 通道失效与协调器恢复停滞

建立：2026-10-14；任务卡补全：2026-10-15（Asia/Shanghai）。类型：缺陷。优先级：P0。状态：已完成（2026-10-16 按本机 Creo 12.4 已验证范围关闭；开发冷态与 WorkBuddy 结论分层，历史完整链未复现事实保留）。目标版本：未排期。

来源：[WorkBuddy 0.3.0 原始报告](../validation/MCP_CREO_MechDog_0.3.0_全量实测问题报告.md) P0-3.3/3.4；证据分层见 [0.3.0 补录](../validation/WORKBUDDY-0.3.0.md)。当前状态统一见[主台账](../BACKLOG.md)。

## 问题与目标

报告称一次 transform 失败后，new_part 的原生保存已返回成功，但 worker 未写出最终结果；约 600 秒超时后，后续 Toolkit 操作返回 `toolkit_code=-38`。`creo_startup_status(retry=true)` 长时间停在 `building_worker`，约 9 分钟无进展；报告中的人工结束 Creo 进程组后，协调器恢复并约 90 秒进入 ready。

目标是定位保存后、结果落盘前及重连路径中的实际卡点，使超时、失联和 retry 都有可判断的状态、明确时间预算及恢复指引；在保护既有模型和未知作业的前提下，验证可安全恢复的通道重新具备建模能力。无法确认结果或无法安全恢复时，保留保护状态并说明需要处理的对象与步骤。

## 实施顺序

1. **确认基线与运行身份。** 实施前核对当前工作区、BUG-009 实际纳入范围、源码/执行器指纹及宿主路径，保留既有未提交内容。开发分支使用 `codex/bug-008-channel-recovery`；仅建立任务卡时不切换分支或开展修复。
2. **建立正常对照。** 在独立测试件上确认真实 Toolkit 连接、新建、一次成功编辑与保存重载；记录 job/model、revision、会话和时间，排除 BUG-005 的初始连接差异。
3. **复现完整故障链。** 核实原 transform 输入及失败阶段，对照“正常任务收尾”“原生失败后新建”“保存后结果未交付”“连接探针超时”。记录实际执行路径的保存、重载/擦除、断开、结果写入、模型登记、终态及锁释放时间；缺原始输入时使用受控夹具并明确差异，不能声称复现了原报告全部因果链。
4. **区分超时类型与预算。** 分开核实构建、等通道、连接探针、原生执行/断开和 retry 总预算；记录预算是否真正生效。无日志增量只作线索，不能单凭静默判定合法长任务挂死。进入开发前把各预算的数值、来源、起止点及到期动作写入本卡和回归断言；历史 600 秒、9 分钟不是验收目标，不先填写未经核实的秒数。
5. **先核对未知结果，再设计恢复。** 只读核对执行器/会话、原生结果、保存文件、模型登记、pending_job 与 revision，区分仍运行、已结束但未交付、连接失效及无法确认。对前述 BUG-009 未确认作业先核对当前状态；无法证明结果时继续保留未知，不重复提交或直接解锁写入。
6. **实施最小修复。** 对已确认卡点实施阶段有界等待、错误传播及安全恢复；并发 retry 复用协调结果，避免重复 worker、重复启动或多个恢复者竞争。状态查询不能排在失联原生调用之后无限等待；无法安全恢复时返回原因、关联对象及人工处理步骤。
7. **完成分层回归。** 先执行受控超时/异常保护回归，再完成本机 Creo 故障前后对照与恢复后建模。故障注入只用于专用测试夹具和受控会话；合成结果或仅重启进程不计为原生恢复通过。
8. **补最终黑盒与交付记录。** 在受测实现身份明确后，由 WorkBuddy 按公开 MCP 场景验收；同步本卡、主台账、适用能力说明和本次证据，保留未测范围。未复现、仅开发者通过或仅有历史报告时不关闭。

| 场景 | 可判断的完成条件 |
| --- | --- |
| 正常保存、收尾与下一任务 | 正常任务取得明确终态，成功修改几何/参数正确、保存重载 true；下一 Toolkit 操作可按单通道契约执行，revision 正确 |
| 原生失败后继续使用 | 失败定位到实际阶段，保留原始错误；检查点、模型与 revision 可核对，恢复后新任务成功，不能只凭保存日志或回滚布尔值判断 |
| 保存后收尾失败或超时 | 阶段与终态/未知状态符合实际，已保存文件及原生诊断被保留；没有可核实成功结果时不发布 succeeded，不自动重做原生操作 |
| 执行器仍运行或结果未知 | pending_job/reservation 和写入保护保持有效，说明占用者或无法确认的原因；不会将无元数据、进程退出或 `-38` 单独当作安全释放/重试依据 |
| retry 和状态查询 | 每次查询在已记录预算内返回；retry 在总预算内成功，或以现有失败/等待契约返回明确结果与处理说明，不能无限停在 building_worker；不预设新状态字段已存在 |
| 故障中的就绪状态 | 历史 ready/connected=true 具有可判断的新鲜度或失效说明；故障后不冒充实时成功，恢复完成以重新取得 Toolkit 连接为依据 |
| 重复 retry 与恢复竞争 | 真实重叠请求或开发者受控并发有分别记录；同一恢复目标不重复启动，写入保护及 BUG-009 通道契约保持有效，无证据则记未验证 |
| 可安全恢复路径 | 无需丢弃未知任务或破坏用户模型即可恢复；连接 code=0 后完成独立小件、新建后一次参数编辑、几何/体积断言及保存重载 true，并检查原测试件/检查点仍可用 |
| 需要人工处理的路径 | 无法安全恢复时停止自动写操作，返回具体原因与下一步；不得把需要人工重启或仍 unknown_outcome 的场景记为自动恢复成功 |
| 回归与兼容 | 适用单元/语言、构建、真实协议与原生测试通过；原错误、占用诊断、revision 和失败保护未退化，服务 stdout 仍只用于 MCP 协议 |
