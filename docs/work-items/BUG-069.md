## 现象与待核实规则

报告称 `creo_new_part(model_name="001")`、`model_name="PRT001"` 均返回 `Invalid model_name`，小写 `prt001` 成功；用户手动打开的模型名为 `001.prt`。未提供这些调用的 job_id 或原始校验返回。

需要先区分 Creo 本体规则、服务创建名规则、服务 model_id 和特征 label。根级规范中“以小写字母开头、最多 28 字符”约束的是特征标签，不能不经核对直接套到模型文件名。“本体允许”也不等于可以直接放宽服务规则。

## 范围与验收

先核对当前公开 schema/描述、服务校验与实际模型名映射，列出大小写、数字开头、长度、非法字符、重名和扩展名的现有行为，再选择最小方案：保留限制并给准确可操作的提示，或在身份/文件规则允许时兼容数字开头和大写。大小写规范化若被采用，须明确回显实际名并检测碰撞；不把名称当路径，不静默改名。

## 2026-10-18：放宽+小写规范化实现（用户确认方案）

规则决策：`bridge.MODEL_NAME` 放宽为 `[a-z0-9][a-z0-9_]{0,30}`（数字开头允许，与 Creo 原生 001.prt 命名习惯对齐）；新增共享 `bridge.normalize_model_name(value)`（先 lower 再 fullmatch，失败抛含完整规则的 ValueError，规则文本注明大写自动转小写）；plate（bridge.validate_spec）、generic submit、adoption apply 三个校验点统一改用，规范化后的名字落入登记/请求（非静默改名：工具描述与错误信息写明，登记回显实际名）。会话同名（大小写碰撞）仍由 native runner 拒绝，无覆盖风险；特征 label 规则（小写 28 字符）不变。

验证：新增 `tests/unit/test_model_naming.py` 6 用例（接受 001/1/PRT001→prt001/1a_b/31 长；拒绝空/空格/连字符/点/下划线开头/32 长/非字符串，错误含完整规则；plate 规范化传递；submit 准入拒绝与登记规范化）；根目录旧用例 `tests/test_validation.py` 同步（A_PART 从拒绝改为规范化断言）。实机 Creo 12.4（build/bug069_verify.py，公开 MCP 接口）：`creo_new_part(model_name="001")` 创建成功（ae20b589…，001.prt.2，saved_file_reloaded_and_verified=true）；`PRTXYZ` 创建回显 `prtxyz`（57f0a2c7…，prtxyz.prt.2）；已有 001 再建（大小写同形）native 拒绝 "New model name already exists"（job ec185a88 failed，无覆盖）。`tools/dev_check.py` 通过（指纹 d1f790de…）、全量单测过、`tools/test_general.py` GENERAL_CORE_SUCCESS=1。未测：Creo 13 外部环境；[验证记录](../validation/BUG-069-BUG-070-2026-10-18.md)。
