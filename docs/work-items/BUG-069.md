# BUG-069：模型名称接受范围与拒绝提示待核实

日期：2026-10-18。类型：缺陷。优先级：P3。状态：待核实。目标版本：未排期。

来源：[0.3.7 / Creo 13 反馈补录](../validation/FEEDBACK-0.3.7-CREO13-2026-10-18.md)第 4a 项；[原件](../validation/feedback-0.3.7-creo13-2026-10-18/report.md)问题 4。关联 [FEAT-008](FEAT-008.md)（输入说明）、[FEAT-042](FEAT-042.md)（已有模型身份）、[BUG-070](BUG-070.md)（显示名异常）。

## 现象与待核实规则

报告称 `creo_new_part(model_name="001")`、`model_name="PRT001"` 均返回 `Invalid model_name`，小写 `prt001` 成功；用户手动打开的模型名为 `001.prt`。未提供这些调用的 job_id 或原始校验返回。

需要先区分 Creo 本体规则、服务创建名规则、服务 model_id 和特征 label。根级规范中“以小写字母开头、最多 28 字符”约束的是特征标签，不能不经核对直接套到模型文件名。“本体允许”也不等于可以直接放宽服务规则。

## 范围与验收

先核对当前公开 schema/描述、服务校验与实际模型名映射，列出大小写、数字开头、长度、非法字符、重名和扩展名的现有行为，再选择最小方案：保留限制并给准确可操作的提示，或在身份/文件规则允许时兼容数字开头和大写。大小写规范化若被采用，须明确回显实际名并检测碰撞；不把名称当路径，不静默改名。

| 环境 / 用例 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| 规则核对 | 比较公开接口、校验和命名实现，保留 `001`/`PRT001`/`prt001` 原始返回 | 说明三种输入拒绝/接受的依据和实际创建名；决定是否改行为，未决定前不宣称命名缺陷已确认 |
| Windows / Python | 修改后 `tools/dev_check.py` 及命名/碰撞回归 | 边界和错误提示一致；拒绝时不创建作业、不改变模型；旧合法名兼容 |
| 创建行为如有变化 | 本机 Creo 12.4 / 匹配 SDK 下逐类创建、查询、保存重载 | 模型名、model_id、登记与文件对应；大小写/重名不会覆盖或误认其他模型；`saved_file_reloaded_and_verified=true` |
| WorkBuddy | 仅调用公开 MCP 验证命名示例与错误 | 用户能按提示修正输入，实际名与返回一致；不能用源码核对代替公开结果 |

仅修正文案时无需原生建模验收；若改变原生/命名行为则执行适用构建与实机检查。本机连接限制和未测环境规则继续有效，不把本次反馈改成已支持新的 Creo 版本。
