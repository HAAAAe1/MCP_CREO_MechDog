## 报告现象（外部环境已证实）

2026-10-18 00:45–00:50（GMT+8）时间线：

1. 00:45:44 `creo_new_part` 成功；约 33 秒后 00:46:17 `creo_execute_plan` 失败：`connect_creo(&process) failed with code -11 during connect`。
2. 00:47:20 `creo_session_status`：`connection_failed` / `toolkit_code -11` / `worker_exit_code 20` / `stale: true` / `retry_allowed: true`。
3. `creo_startup_status(retry=true)` 走到 `waiting_for_connection` 后于预算内 `timeout`（coordinator 停止），`launch_attempt` 累计 5 次仍失败，自动重连无法自愈。
4. 进程快照：`xtop.exe`（pid 4036）与 `parametric.exe`（pid 2652）已运行约 530 分钟，`Responding=True` 但 **`MainWindowHandle=0`（无任何主窗口）**，Toolkit 无法在其上建立连接。
5. 人工恢复路径（外部实测有效）：结束无主窗口的 `xtop.exe` / `parametric.exe` / `creoagent.exe` 残留进程 → `creo_startup_status(retry=true)` → 协调器拉起新会话（`launch_attempt: 6`），约 40 秒后 `connected: true` / `state: ready`，通道完全恢复。

## 待核实根因与分层

- 无主窗口的 Creo 进程是"会话启动失败的残骸"还是"会话丢失主窗口"，未定；在此状态下 Toolkit 连接稳定返回 -11。
- `-11` 与 [BUG-001](BUG-001.md) 批次 A（-97/-11，请求到达 Creo、初始化失败）同码；BUG-001 已按用户决定关闭但卡死根因未定，本条按独立缺陷登记，不据此重开 BUG-001。
- 与已关闭的 [BUG-056](BUG-056.md)（nmsd 名字服务层 -4，trail 证明请求未达 Creo）为**不同层失败**，不重开。反馈推断"33 秒窗口与 37～41 秒高度吻合故同缺陷"不成立：BUG-056 调查已证伪固定节奏（表观节奏来自客户端按快照 stale 期轮询），且两者错误码层级不同。
- 自动重连为何不能恢复：`launch_attempt` 递增但旧进程未被处理，新会话与残留进程的关系需核对协调器逻辑。

## 范围

- 恢复指引与自动重连的核对限于 `creo_startup` 协调器、`creo_startup_status`/`creo_session_status` 的状态与提示路径。
- 反馈建议登记为候选方向，不预先承诺：`waiting_for_connection` 且检测到"Creo 进程存在但无主窗口/无连接"时给出"结束该残留进程后 retry"的具体指引（当前只提示 Check startup dialogs，对无窗口进程不适用）；评估仅在"进程为本服务 launch 拉起"时自动清理后重试——须严格限定自身拉起的进程，不得误杀用户会话。
- 本机联调约束（停止新的 Toolkit 连接/故障注入）仍然有效；实机核实按外部反馈或用户授权的环境进行。

### 2026-10-18 DEV-040 代码核对

协调器 inventory 仅按 Windows session、映像路径及进程身份判断，不读取 MainWindowHandle，无法区分“进程存在但无主窗口”；匹配进程存在时只继续连接探测并 waiting_for_connection，不启动替代会话。提示统一建议检查对话框。launch_attempt 仅在实际准备 launch 时递增，不是 retry 计数；外部计数增长还需各时点进程可见性与历史状态证据。

当前没有自动结束 Creo 的路径，launcher 也未返回新 Creo 的 PID/创建时间，不能凭 launched_by_coordinator 布尔量清理进程。本轮只读核对，未修改提示或实现、未新增 Toolkit 连接、未实机复现 -11；状态保持待复现。详见 [DEV-040 离线记录](../validation/DEV-040-offline-2026-10-18.md)。
