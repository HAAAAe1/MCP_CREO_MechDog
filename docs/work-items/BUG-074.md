# BUG-074：无进程身份的历史作业永久阻断模型恢复

日期：2026-10-20。类型：缺陷。优先级：P1。状态：验收中。目标版本：未排期。

来源：0.3.7 剩余反馈处理计划及 2026-10-18 Creo 9 第七轮报告；关联 FEAT-018、BUG-059。

## 现象与范围

旧作业缺少 runner/native owner PID 和创建时间，inspect 将身份缺失等同无法证明停止，四动作均永久不可用。新增可核验的跨 Windows 启动停止证据，仍保留每种动作原有条件、所有权、令牌、revision、幂等和锁内终态保护。不清理用户文件、不结束进程、不自动重交原作业。

复用 windows_boot.boot_info 的 WMI 与内核时钟交叉核验；只接受绑定本模型、控制记录及记录时间均在已核实启动前的历史作业。身份完整但活动或查询不确定的所有者不走历史兜底。同次启动、证据缺失、时间异常、文件变更及启动时间不可核验均拒绝，并给操作指引。证据进入 token 绑定，准入和执行前重新校验。

## 验收标准

- Windows/Python：先用隔离旧作业复现四动作禁用，再验证跨启动证据只解除 owner 门槛，各动作仍有自身条件。
- 覆盖同次启动、时钟不一致/查询失败、记录缺失、文件触碰/替换、活动 owner、证据过期、幂等和准入后变化；全量单元及 dev_check 通过。
- 原生与 WorkBuddy 分层记录；隔离夹具不作为真实恢复通过，现有 Toolkit 连接/注入限制继续适用。

## 实现与证据

实施基线 main cfcea22（0.4.2），分支 codex/bug-057-feedback-037。10 项新增隔离回归及全量 455 项单元、dev_check 通过。真实跨启动作业的原生恢复、续作及 WorkBuddy 未验证，不能以夹具代替。会话就绪探测失败前未提交任何建模或恢复作业，现有保护保持。详见[本轮验证记录](../validation/FEEDBACK-0.3.7-IMPLEMENTATION-2026-10-20.md)。
