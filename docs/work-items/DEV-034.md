## 验收矩阵

开发者协议夹具使用隔离数据根和受控模型/作业，不修改用户历史失败件；夹具不连接 Toolkit，其结果明确记为协议/业务测试。真实恢复使用测试发起者事先明确选择放弃/恢复的自有模型，不因 inspect 显示 available 就自动代替操作者作决定。

| 场景 | 输入/操作 | 可判断的预期结果 |
| --- | --- | --- |
| T01 标准 null | pending=null、revision=0，使用本次 inspect 的 token，经 MCP apply abandon_new | 服务收到 JSON null 对应值，证据未变时不误报 stale；协议夹具成功进入合法提交路径，真实环境按 T08 核对终态 |
| T02 省略字段 | 同模型省略 expected_pending_job_id，与显式 null 对照 | 核实当前默认值兼容及公开契约；允许时与 null 一致，要求显式提交时给准确输入错误。不得让省略掩盖实际非空 pending |
| T03 非法/兼容空值 | 空串、空白、字面字符串 null、错误类型 | 按 G2 明确拒绝或有边界兼容；记录实际传输值，不能把错误输入都折叠成 None，也不误宣称模型真的发生 revision 冲突 |
| T04 非空 pending | 当前真实 pending ID、错误 ID、实际非空却传 null | 精确匹配才进入后续校验；错误/不匹配拒绝，原作业、模型、revision 和保护不变 |
| T05 真实 stale 与授权 | revision 改变、token 过期/不属于本模型、绑定文件/部署或 owner 改变 | 仍准确拒绝且不执行动作；不自动续期、清锁或换 token 重试。时间/文件/进程变化由离线夹具模拟，不要求 WorkBuddy 注入 |
| T06 幂等和占用 | 相同键相同请求、相同键改动作/参数、已有 recovery_pending 或活动 owner | 重复请求按正式幂等契约处理，不重复处置/推进 revision；冲突或占用拒绝并提供可取得的原因，保持 busy 不排队 |
| T07 共享动作契约 | 对 restore_baseline / accept_saved / accept_live / abandon_new 分别使用适用与不适用的受控证据 | 参数适配与授权规则一致，accept_live 的实时预检要求不被空值修复绕过；协议夹具通过不标为四动作实机通过 |
| T08 真实 MCP 闭环 | 新鲜 inspect→操作者明确选择→apply→仅轮询原恢复 job | abandon_new 达 succeeded、模型 abandoned、历史保留且 revision 不推进；不强求该动作的保存重载标志。若测试 restore/accept，则按正式规则验证 revision、几何/参数及 saved_file_reloaded_and_verified=true，适用时后续编辑成功 |

## 实现落点与验证方式

优先核对 `server.py` 的注册/适配与 `src/creo_mechdog/reconciliation.py` 的业务校验，沿用 `tests/unit/test_reconciliation.py` 和已有协议测试设施。新增 Python 业务逻辑放包内，入口不堆业务规则；没有证据时不改 native、模型状态文件或恢复预算。

拟新增聚焦的 `tests/unit/test_reconciliation_mcp.py` 或等价协议回归（当前未新增），必须经过实际工具注册/schema/stdio 传输，不能只 mock 掉 MCP 后直调业务函数。夹具可替代原生执行，但必须标明该替代边界。开发者运行针对性回归及 `tools/dev_check.py`；涉及原生行为才补匹配 SDK 构建和对应实机用例。现有 `tools/test_model_reconciliation.py` 的故障注入入口不能未经核对整体重跑。

WorkBuddy 交接文档在实现/开发验证后生成，只提供 MCP 场景、输入、预期和报告要求。由发起者提供可用且已明确处置动作的测试模型；WorkBuddy 通过公开接口确认部署、inspect→apply→creo_get_job，不读源码/配置、不跑本地脚本、不直接调 Python/内部 runner，也不重放原异常计划。记录 schema 可见性、实际参数形状、job_id/model_id、终态、错误、revision、审计及适用几何/保存重载；不能发送所需输入时如实记客户端阻断。

新证据分别记录 Windows/Python/Creo/SDK/编译器、日期、条目、服务版本、受测 commit、dirty、源码/产物指纹及命令/原始调用。本机 Creo 12.4、外部 Creo 9 和纯协议夹具分别记账；不新增双版本或 Creo 10 独立发布门槛，不把 null 问题只靠本地单元通过就标为 MCP 已修复。
