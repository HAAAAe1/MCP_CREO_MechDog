# BUG-007：已有件追加放样挂死并长时间占用 Toolkit 通道

日期：2026-10-14。类型：缺陷。优先级：P0。状态：验收中（修复及Creo12.4开发者原生回归通过，待WorkBuddy最终MCP验收）。执行顺序：当前项，继续实机与WorkBuddy验收。目标版本：未排期。

来源：[WorkBuddy 0.3.0 原始报告](../validation/MCP_CREO_MechDog_0.3.0_全量实测问题报告.md) P0-3.1/3.2；证据性质与覆盖缺口见 [补录摘要](../validation/WORKBUDDY-0.3.0.md)。

## 目标与当前证据

Creo 12.4.0.0 / MCP 0.3.0 下，已有零件 t30_loft2 创建 XY 草图 sk_a（R10@Z0）、sk_b（R6@Z25），追加 `creo_loft(sections=[sk_a,sk_b], mode="add", interpolation="straight")`。报告记录作业停在 running / activate_blend_context，约600秒后 unknown_outcome；期间 Toolkit 调用 busy，种子新建放样对照成功。报告未提供精确完整草图输入或 job_id/model_id，复现前须补齐。

目标：消除一次直接放样调用长时间锁住 Toolkit 通道的情况。在支持环境中创建真实原生 Blend；受限环境在进入不可控等待前给出原因及可行动提示。失败不能破坏已保存模型，也不能把其他正常任务长期挡住。

报告根据源码/日志/窗口检查推测 UI 宏、运行时 DLL 加载或交互状态导致等待。这些是开发者复核线索，尚未独立确认卡点，不能把“改用种子”直接当已确定修复方案；已有件追加特征与新建种子件也不能互相替代。原始调查时的代码可读到 `ProToolkitDllLoad` 和 `ProMacroLoad` 调用，只能证明这些路径存在，不能证明哪一调用导致本轮挂死。

## 范围

核实已有件直接放样的连接、加载、创建阶段与超时处理；建立支持/受限输入、交互等待与未知结果的可行动返回，验证失败后的通道与模型保护。通道损坏、断开收尾及协调器恢复另归 BUG-008，取消能力归 FEAT-021。不得通过盲清 pending_job 或自动重交未知任务释放通道。

保持 `creo_loft` 与 `creo_execute_plan` 中 loft 操作的契约一致，保留标签/ID引用、revision保护、失败回滚和保存重载。本卡不扩展 cut/surface/new_body、非平行截面或任意约束，也不把已有件替换为种子新件来声称修复完成。若直接放样只能降级为明确受限，登记为止损范围，不能按完整功能修复关闭本项。

## 最小复现输入

以下按当前接口重建，可作为新的最小复现，不冒充报告遗失的原始输入。使用独立测试模型，不复用报告中的 t30_loft2，也不修改用户模型。

1. 查询 `creo_capabilities`、`creo_session_status` 和 `creo_startup_status`，记录公开可见的服务/Creo版本、工具和连接状态。无法由MCP确认的构建身份记为无法确认；开发者另记录源码身份。
2. 调用 `creo_execute_plan`，省略model_id新建零件，创建两个同轴XY圆草图：

```json
{
  "model_name": "bug007_circle_probe",
  "operations": [
    {
      "op": "sketch",
      "label": "sk_a",
      "plane": "XY",
      "offset": 0,
      "entities": [{"type": "circle", "name": "c_a", "center": [0, 0], "radius": 10}]
    },
    {
      "op": "sketch",
      "label": "sk_b",
      "plane": "XY",
      "offset": 25,
      "entities": [{"type": "circle", "name": "c_b", "center": [0, 0], "radius": 6}]
    }
  ]
}
```

3. 只轮询返回的job_id直到终态；确认两草图创建成功并保存重载后，保留该检查点、实际model_id和revision。然后单独调用 `creo_loft`：

```json
{
  "model_id": "<上一任务实际返回的model_id>",
  "expected_revision": 0,
  "label": "blend_probe",
  "sections": ["sk_a", "sk_b"],
  "mode": "add",
  "interpolation": "straight",
  "new_body": false
}
```

**调用前必须把expected_revision替换为上一任务的实际revision，示例中的0不是约定值。** 只提交一次，持续查询同一job_id，记录stage/终态/耗时。若卡住或unknown_outcome，先核对该任务和模型，不自动重新提交、清锁或清pending_job。

4. 成功时查询原生特征、两截面、体积与保存重载；独立新建件中的圆台期望体积为 `4900π/3 ≈ 5131.26800086 mm³`，z范围0..25。失败时核对草图检查点、revision、残留特征及回滚；未知结果不能默认当失败回滚成功。
5. 原任务结果和连接状态可确认后，用独立小件验证通道仍可执行并保存重载。另以 `creo_new_loft_part` 使用相同两截面做种子对照，分别记录任务；两条路径不能互相代替。
