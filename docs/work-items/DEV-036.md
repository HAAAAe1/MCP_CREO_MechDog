## 验收矩阵

探测自身可能改变空闲条件，因此不能只连续探测就排除空闲问题。进入实机阶段后，先做一次至少 60 秒不调用 Toolkit 的空闲对照，再按实际探测耗时以约 10 秒起始间隔串行观察至少 5 分钟；之后再做空闲对照。任一阶段异常即停止后续调用，下一次调查先重新核对会话条件。这里的间隔是调查采样安排，不新增产品自动重试机制。

| 场景 | 命令或操作 | 可判断的预期结果 |
| --- | --- | --- |
| T01 状态与时效 | 离线夹具对照 startup snapshot 的 `verified_at`、`verification_age_seconds`、`stale` 与实时探测结果 | 快照陈旧不被当作实时断连，历史 ready 不掩盖新的失败；准确保留原始错误、验证时间和可取得的会话身份 |
| T02 失败分类 | 受控夹具覆盖连接 -4、探测退出 20、超时、进程退出、会话歧义和 busy | 原因与来源可区分，不随意挑选另一会话，不自动启动/重连，不改写模型保护。夹具不连接 Creo；不能用它证明真实掉线根因 |
| T03 时间线与空闲对照 | G1 成功后，执行上述空闲/间隔探测，并记录 PID/创建时间、原始返回和实际间隔 | 当前版本是否复现有明确结论；异常时间与最后一次成功验证可比较。失败时保留完整记录并停止，不用重复重连掩盖失效 |
| T04 修复或规避验证 | 同一可操作会话完成至少 5 分钟探测及至少 60 秒空闲后再次探测 | 全程连接成功，无约 40 秒失效，Creo GUI 保持可操作；明确该窗口只覆盖本次环境，不能据此宣称无限期稳定 |
| T05 正常建模闭环 | 自有唯一名称简单零件，经 MCP 新建、编辑、保存重载，再空闲至少 60 秒后探测 | 作业仅轮询原 `job_id` 到终态；原生几何/参数和 revision 正确，`saved_file_reloaded_and_verified=true`，任务前后及空闲后通道正常 |
| T06 异常与保护回归 | 离线协议/业务夹具覆盖 unknown、已有 recovery_pending、活动 owner 与幂等；必要的自然失败用例单列 | 不重放原计划、不清保护、不偷换会话，不重复恢复或推进 revision；不整体重跑强制中断/卡死注入脚本 |
| T07 稳定通道下协议对照 | 新建且已明确允许处置的测试模型，用省略字段和客户端能真实发送的合法空值走 inspect→apply→轮询 | 各自符合已发布空值契约，记录实际可发送形状与终态；不能发送 JSON null 时记客户端限制。字面 `"null"` 按现有 SDK 行为记录，不改变 BUG-055 已完成结论 |
| T08 原 M2 交接 | 稳定后通过公开接口读取旧模型/作业，并报告下一步所需条件 | 原 unknown 与审计保留，明确已完成/未完成/接口不支持的范围；没有发起者明确处置选择时不 apply。原 M2 仍未处置不妨碍如实验收 BUG-056 本身 |

开发者按实际改动运行 `tools/dev_check.py` 及启动/协调/恢复的针对性回归；修改校验或保护逻辑须补 `tests/unit/test_*.py`。涉及 C++ 连接行为时补匹配 Creo 12.4 SDK 构建及受控连接/建模验证；涉及原生建模代码时运行对应 `tools/test_*.py` 并取得几何、保存重载和适用回滚证据。`tools/test_startup_retry.py`、`tools/test_model_reconciliation.py` 等实机入口先核对场景，不能未经核对整套执行。

WorkBuddy 提示词在实现和开发验证后另行生成，只提供公开 MCP 场景、输入、预期和报告要求。WorkBuddy 不查看源码/Git/本机配置，不执行本地脚本，不采集内部进程/文件证据；公开接口未提供的身份、根因与内部机制记为“无法确认/未验证”。建模、保护和参数结论以工具实际返回及 Creo 实际结果为准，不用本地 Python 直调代替 MCP 闭环。
