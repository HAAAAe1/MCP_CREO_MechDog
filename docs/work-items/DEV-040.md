# DEV-040：复现并修复 BUG-057 锁文件竞争与 BUG-059 恢复拒绝终态

日期：2026-10-18。类型：工程整理（缺陷修复执行卡）。优先级：P1。状态：待开发。目标版本：未排期。

来源：[BUG-057](BUG-057.md) 与 [BUG-059](BUG-059.md) 均为 2026-10-18 登记的外部 0.3.5 反馈缺陷，按[主台账当前安排](../BACKLOG.md)第一条优先处理。[BUG-058](BUG-058.md) 的协调器代码核对可并入本卡离线阶段，实机复现部分暂缓（停止 Toolkit 连接约束仍有效）。执行卡不改变两张缺陷卡的状态与结论。

## 目标

- BUG-057：在本机复现或证伪 `toolkit_lock` 并发准入的 `PermissionError [Errno 13]`，确认机制后按最小影响修复，单测恢复全绿。
- BUG-059：确认恢复执行前拒绝（会话变更/证据过期）的判定阶段，把确定性拒绝从 `unknown_outcome` 语义中分离，并消除 `recovery_pending` 悬挂。
- 两项都以离线路径优先：单元测试与受控夹具，不连接 Creo。

## 阶段安排

| 阶段 | 内容 | 完成判据 |
| --- | --- | --- |
| G1 | 本机复现 BUG-057：`python -m unittest tests.unit.test_reconciliation` 连续多次（建议 ≥10 次），记录 Python 版本、次数与结果分布 | 复现则留最小复现脚本；证伪则记录与本机/外部（Win10 19045 / Python 3.13.14）的环境差异，不直接关闭 |
| G2 | 定位：验证 delete-pending / sharing violation 假设；必要时用最小脚本在 `TemporaryDirectory` 交错 open/unlink 取证 | 给出可复核的机制结论（哪条路径让锁文件名进入不可打开状态），区分"打开失败"与"持锁者存在" |
| G3 | 修复选型与实现：常驻锁文件、`open` 短重试、`FILE_SHARE_READ\|WRITE\|DELETE` 三方向按证据选最小方案 | Errno 13 与 `ToolkitBusy` 分开报错；不引入排队或自动重试语义；busy 立即拒绝行为不变 |

| G5 | 回归：`tools/dev_check.py` 全量、恢复相关单测（含 BUG-055 契约用例）、BUG-057 原失败测试多次运行 | 全部通过；真 unknown 保护、空值契约与幂等不退化 |
| G6 | WorkBuddy 黑盒验收（仅当 G3/G4 改动触及 MCP 可见行为） | 拒绝路径终态、字段与文档一致；锁语义对客户端不可见变化记录在案 |

## 范围与边界

- 不连接 Toolkit、不重启/结束 Creo、不清任何 unknown/recovery_pending 保护（本机联调约束）。
- BUG-058 仅做协调器"进程存在但无主窗口"分支的代码核对与结论记录，实机复现、指引改动与自动清理另行排期。
- FEAT-034（弧方向）不在本卡范围；如与本卡抢排期，按台账优先级另行决定。
- 修复不放宽任何保护：revision/pending/凭证校验、token 600 秒时效、跨会话指纹拒绝语义均保持。
