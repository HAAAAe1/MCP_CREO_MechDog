# BUG-005：Codex stdio 客户端 Toolkit 连接复测失败

类型：缺陷。优先级：P1。状态：待核实。建立日期：2026-10-13。目标版本：未排期。

来源：[FEAT-019 最终验收](../validation/FEAT-019.md)。范围为当前 Codex 客户端/本机通信环境的连接差异；不修改 WorkBuddy 已通过的独立验收记录。

## 已证实现象与待核实根因

WorkBuddy 在 E 盘开发版 MCP / Creo 12.4 中完成自动启动、真实 Toolkit 连接和完整建模。Codex 重启后挂载接口仍为 80 个工具，缺少 startup/runtime；该接口 status 返回 -4。随后 Codex 直接启动 E 盘开发版 stdio MCP，公开 runtime 核对正确、源码未漂移；零 Creo 进程条件下请求启动并显式 retry，GUI 出现，探测曾返回 -4，随后 configuration_error（TimeoutExpired），未提交新模型。

另一个开发版 MCP 客户端可以只读查询 WorkBuddy 成功任务和模型，复核 6 个任务成功且保存重载通过、revision=6 / volume=9980 mm³。初始化与任务登记读取可用不等于当前 Toolkit 连接可用。

当前不能断言为 Codex 权限、SDK、许可、名称服务或客户端配置导致。需要在同一个保留中的 Creo 会话上，对照两种客户端的实际运行身份、环境、连接时序和终态；初始旧挂载接口与后续独立开发版探测分别记录。

## 验收方式与环境

Windows x64、Python 3.12.14、Creo 12.4 / 匹配 Toolkit SDK（实验兼容）。先复现并记录客户端差异，再确认受测环境的 Toolkit code=0 / connected=true；完成一个独立小零件、几何断言和保存重载，不关闭用户已有会话、不自动重复提交未知结果任务。涉及代码修复时运行对应单元与语言检查；Creo 10 正式基线另列。

当前证据：源码 efc0292、复测前 dirty=false；公开源码指纹、启动终态与本地原始报告 SHA256 位于 [FEAT-019.json](../validation/FEAT-019.json) 的 acceptance.codex_new_cold_start_smoke。原始报告保留 build/FEAT-019-codex-smoke.json，本次未开展修复。

## 2026-10-14 同会话诊断范围

用户确认Creo已进入可建模界面、WorkBuddy没有该异常，授权继续排查Codex连接差异，作为BUG-007的连接前置。先只读对照Windows会话/用户、名称服务登记、允许记录的通信环境变量和原生连接；不关闭Creo、不修改用户模型、不泄露许可或敏感连接标识。必要时通过现有交互桌面隐藏启动相同探针，区分宿主与环境影响。

已证实相同原生探针在Codex子进程中返回-4，经现有Explorer桌面隐藏启动则返回0，当前模型读取、release_numeric=44与断开均成功。同一Windows用户/会话、PTC名称服务有当前Creo登记；display/user过滤放宽仍-4，隐藏控制台及通信程序长/短路径也未消除现象。尚未区分具体宿主限制与环境变量差异，不直接归因于权限、Job Object或某个变量。此桌面路径用于BUG-007开发者实机诊断，不是已交付的自动连接修复，也不冒充WorkBuddy复测。

BUG-007通过该路径完成2000mm³独立小件和两截面检查点（保存重载通过），直接loft作业随后进入等待。当前任务/模型ID及对照原始返回见 [BUG-007开发证据](../validation/BUG-007.json)。后续确定连接根因、形成最小修复并完成公开MCP回归前，BUG-005仍待核实。

用户补录WorkBuddy当前公开摘要：connected=true、connection_state=connected、C:/MCP_CREO_MechDog、该目录.venv/Scripts/python.exe、version=0.3.0。这是用户提供的同会话接口对照，不代表Codex宿主连接差异已修复；实际宿主根因仍未确定。
