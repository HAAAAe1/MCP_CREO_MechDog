## 2026-10-18：本机复现取证与修复

取证（本机 Creo 12.4 可复现，同形态）：带原生环境直跑 `creo_worker.exe status 5`，stdout 原始字节即含 `e2 96 a9`（U+25A9）+ 大写名 + `0001`（例 `▩STB_3395F2E70001`）——异常产生于 native 读取层，非编码转换/JSON 序列化/客户端显示。根因：`native/worker.cpp` status 探针使用 deprecated（since Creo 3）`ProMdlNameGet`，其 `ProName` 输出缓冲未初始化且返回值未检查；失败时缓冲保持 connect 阶段 Toolkit 内部调用留下的栈残留（0x25A9 前缀+名字+0001 形态）。

修复：改用继任 `ProMdlMdlnameGet`（ProMdl.h:595 SUCCESSORS）+ `ProMdlName value = {}` 零初始化 + 返回值检查（失败名置空），新增 `name_read_code` 诊断字段。不在 Python/客户端层做字符清洗掩盖（卡内原则）。

验证：探针复跑返回 `"current_model":"STB_3395F2E7"`（无 ▩ 无尾缀，name_read_code=0）；MCP `creo_session_status` 双层复验 `"PRTXYZ"` 干净可读（build/bug070_mcp.json）；切换当前模型（两次创建后）不夹旧值/尾缀。单测/回归与 BUG-069 同批（dev_check、全量单测、test_general 全过）。未测：Creo 13.4.1.0 外部环境（同代码路径推断无版本差异但未实测）；无当前窗口模型场景（name_read_code 可诊断）。[验证记录](../validation/BUG-069-BUG-070-2026-10-18.md)。
